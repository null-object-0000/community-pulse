### [开源]「Flotilla v1.0.0：让 AI 一次管理所有服务器，但每一步都过人审批」 👤 MuskZhou
> > 本人文笔不佳，写不出想表达的意思，以下内容有部分是 ai 代笔后我再进行更改，或者让 ai 帮我调整更美观的格式，提前抱歉 > 如果各位对于本项目有任何的建议或者想法，可以随时私信我或者提 issue ，第一次写这种项目，请各位多多包容 我之前在自己做梯子的时候，老是需要在好几个 ssh 里面跳来跳去，有时候还会输入指令给错的服务器，每次让 ai 做小改动，都要给他说每台服务器的基本情况。但是现在找到的 mcp 服务又大多是单台服务器，不是跨服务器的。 所以我就写了 Flotilla 这个项目：一个把整个服务器舰队当成一个整体来管理的 MCP Server 。 ![image]( https://mac-dropbox.s3.bitiful.net/0-banner.png?no-wait=on) ### 我想先讲讲在我实际使用中它解决了我的什么问题 1. 只需要和 agent 说一句话，他就会自动获取我所有服务器的状态，他们之间的联系 2. 我让 ai 帮我做一个线路+落地的节点，全部不需要我在两台服务器操作，它自动在两台服务器执行需要的命令 3. 让他获取我们所有服务的 nginx 状态和情况，可以直接做出一个网络拓扑图 ![image]( https://mac-dropbox.s3.bitiful.net/3-exec-picker.png?no-wait=on) ### 安装与运行模式 做 Flotilla 的初衷就是因为我不想在多台服务器之间跳来跳去——所以安装被压缩到一句命令： ```bash curl -fsSL https://raw.githubusercontent.com/paipaiio/flotilla-mcp/main/deploy/bootstrap.sh -o bootstrap.sh bash bootstrap.sh ``` 脚本自动识别系统环境（有 Docker 用 Docker ，有 Node ≥ 20 用 Node ，都没有就自动装 Docker ），然后引导入网第一台机器、生成 token 、拉起服务——空白服务器到上线约 10 分钟。重复执行是安全的：续走未完成的部分，不重复建容器/服务。 #### 模式一：本地运行 装在自己的 MacBook 或者工作机上，本地以 stdio 暴露 MCP ，接进 Claude Code 、Cursor 等 harness： ```bash claude mcp add --transport stdio flotilla -- flotilla-mcp ``` 私钥和配置只存在你自己的机器上，信任边界最清晰；和 Claude Code 本地体验无缝——审批弹窗、交互式确认全可用。 #### 模式二：网站模式（团队 / 云端 agent ） 部署到一台服务器，把整个舰队暴露为一个带 token 鉴权的 HTTPS MCP 端点。两个典型接法： - **网站连接器**：Grok 等平台的自定义 MCP 连接器，直接填 URL + token - **聚合服务**：Cloudflare 这类 MCP 聚合/代理服务背后挂它 ```bash bash bootstrap.sh # 同一脚本；装完把 127.0.0.1:PORT 反代到 Caddy/nginx （模板见 deploy/） ``` fleet 随即成为 `https://mcp.example.com/mcp`。团队新机器入网只需一行 `join.sh --token `，人和 agent 走同一个入口，同一套策略与审计。 附图： ![image]( https://mac-dropbox.s3.bitiful.net/2-dashboard.png?no-wait=on) ![image]( https://mac-dropbox.s3.bitiful.net/4-enroll.png?no-wait=on) ![image]( https://mac-dropbox.s3.bitiful.net/3-exec-rolling.png?no-wait=on)
