Router 层是整个系统的中心 其实它就是 SA，对外承担了交互的职责，统一和人对接，同时接入各个渠道，如 IM，Github，Slack，WeChat，Gmail 等等，对内统一管理下面的 Agent Worker，将他们的上下文统一在一个平面上。 再回顾下我之前的工作状态，其实是用它来替代了我这个「人肉 Router」，作为我的助理向我汇报工作，是我们个人管理项目成为可能。 ![]( https://i.v2ex.co/R5cQ39P2.png) 从 Router 这个角度看，有点像年初的 OpenClaw 小龙虾，但是差距还是非常大，后面有时间可以对比几个类似的产品。 #### 2. 面向「任务/Task」的设计 文中详细描述了 Router 层所要处理的跨任务信息和决策，重点讲解了事件驱动的消息路由过程和设计。 但让人要面对的对象还是 Session，可以理解为是一个上下文统一、独立完整的工作流程，因为 LLM 的加入会更加智能。但要想实现复杂项目管理的目标，还涉及到工作流程的调度，项目人员的管理和分配，资源的配备等等。 所以在产品落地的过程中，引入了「Task」的概念，让人真正在项目中只需要参与「任务」的管理，同时保留 session 等细节可供执行回溯。同时它也让 SA 在水平方向上的拆分成为可能，因为文中也指出 SA 在事件路由过程中并不会成为瓶颈，没有必要再水平方向上扩展。下面右边侧边栏是「任务」列表界面，点击后可进入「任务视图」： ![]( https://i.v2ex.co/GqMsP77O.png) #### 3. 异步 ReAct 架构 从整体上看，Router 和 Worker 这套架构就是一套异步的 ReAct 方案。Router 派发消息给 Worker，并不用等待，立马可以处理下一条，多条消息同时到达也可以同时处理，增加吞吐量。当 Worker 结束任务后上报处理结果，Router 返回给用户。ReAct 就体现在更加复杂的异步调度上，由于「Task」的引入，不同 session 可以并行，可以 if-else，也可以 wait-continue 等等。 ![]( https://i.v2ex.co/L5gLchf7.png) 作为异步任务的执行，我觉得大家对执行时间的包容度还是很大的。它做它的，我去干别的，等它做完收报告。 其实没有太明白 DeepSeek Harness 为什么引入异步 ReAct，从架构上就可以了。 ### 3. 产品落地过程 10 天的落地过程主要分 3 步骤，前期主要使用 Opus5.5 和 Fable5.1，但在后面设计 Router 的过程中它们降智非常严重，经常一个问题也说不到重点，那几天基本都吵架到深夜...好在过了两天 Fable5.2 发布，开始有了进展。 #### 1.统一设备、agent 的接入，作为 worker 资源提供 开始做的第一步，我并没有去实现 Router 相关的部分，而是先将所有的本地 Coding Agent 搬到线上，统一管理。这个是很早就有的想法，是非常独立的一部分，本身就能非常大的提高产品体检和效率： - 可以随时、随地接入，而不用守在电脑旁边 - 独立的 Agent 资源隔离，角色、任务、工具、技能等等可以定制化和可视化。制作出非常多独立轻量的 Bot。这个也非常重要，反观很多桌面类产品将很多东西大杂烩，产品设计就是堆功能，用户体验就是摸不着头脑。 - 组合各家 Coding Agent，使用最强 Harness 和 LLM 所以第一步就是物理上拉通所有的电脑等设备，逻辑上拉通所有的本地 agent，可以作为底层的 woker 作为调用。所以先发布了 Crewbot，一个开源的 daemon，在每台设备上安装一下（后期可能集成进桌面版，用户感觉会更好），具体介绍和仓库在： ``` https://github.com/nifengxiaofei/crewbot-connector ```` 安装后的效果就是: ``` (base) test1@MacBook-Air daemon % crewbot status crewbot 0.2.7 (protocol v2) Daemon status running (pid 65637, up 1d 23h) server https://super-agent.team — reconnecting for 7m agents 0 process(es) running account linked Device hostname MacBook-Air.local os darwin (arm64) Agents Claude Code 2.1.321 ✓ ready Codex 0.166.0 ✓ ready Grok 1.0.77 ✓ ready ``` ![]( https://i.v2ex.co/tk6Tvb33.png) #### 2.每个 bot 都是独立的，可在线派任务 为了最大兼容之前的工作模式，接入后每个 Bot 都是一个独立的执行个体。和它们对话、派任务就和在本地 CLI 使用没有区别，所有「数据」、「订阅」或者「API」使用的都是本地设备上的。 >这些 CLI Agent，如 Claude code，Codex，Deepseek Harness 等都是大量的工程实践，配备专业的模型才是最佳实践。 我最喜欢的一个功能就是自定义每个 bot，给它配备不同的 skill，帮我执行任务，利用开放的专业技能，大大扩展我的个人能力。我也将 skills 市场集成了进来，搜索和安装一键合成，我可以轻松配备一个 Bot 军团为我干活，评估效果。 >现在市面上 agent 落地方式最多基本都是 agent+skill，bot 已经帮你轻松组织好了。 ![]( https://i.v2ex.co/6gsN02Y9.png) 而且至此，这些产品的功能都是「**免费**」给大家使用，只需要线上注册一个账号就行了。 #### 3.接入 Router 上面的这些功能将你本地的 Agent 团队带到了云端，worker 工作环境还是留在本地。但你还是一个大管家，只是交互体验和隔离性更好了。要真正实现「项目管理」，还需要加入智能助手 Router。 任何的项目或者任务管理都需要： - 1、创建任务和目标，查看分配任务，查看任务目标，验收任务 - 2、给任务和目标配备资源，这里就是干活的 bot，配备不同工具、技能和资源 ![]( https://i.v2ex.co/sfW9guN3.png) 现在可以从 web 端，手机 web 端接入发消息。Router 根据消息将任务派发给 Bot，bot 干完活回来报告给你。事件驱动和投机执行都能轻松实现。 #### 4.后续的功能规划 形成一个更加完整，功能强大的产品还需要后续的一些规划： - ### Casvisor： JumpServer 之外的开源堡垒机， Apache-2.0，一个 Go 二进制装下 SSH / RDP / VNC / Telnet 👤 Casbin
> 团队里管着几十台服务器，最后都会走到同一个问题：谁在什么时候连了哪台机器，做了什么？ 常见的做法是共享账号、把 SSH 密码发在群里，或者大家一起用同一个跳板机账号。真出了事，登录日志里只有一行 IP ，查不到人；有人把密码带走，也无从知道。 堡垒机就是解决这个的。但看了一圈开源的选项： - JumpServer：国内事实标准，但 RDP 代理、数据库的原生客户端代理（ Magnus ）、远程应用这些放在企业版里； - Teleport：AGPL ，社区版二进制对企业规模和收入有限制； - Next Terminal：2.0 起服务端闭源，免费版限 100 个资产； - Boundary：仓库已经归档； - Warpgate：Apache-2.0 ，Rust ，单二进制，是目前最接近「完全开源」的对手。 我们想要的是：功能完整、一个二进制就能跑、能接自己的 SSO 。找不到，就自己写了 Casvisor 。 ### 连接 **SSH**：网页里是 xterm.js 终端，旁边带一个文件面板，走 SFTP 上传下载。 **RDP**：自己写的纯 Go 客户端 [gordp]( https://github.com/casvisor/gordp)，支持 NLA 、GFX 图形管道（ ClearCodec 和 RemoteFX Progressive ，和 Windows 自带客户端一样的画质路径）、高 DPI 下的清晰字体、远程光标、剪贴板、跟随窗口改大小、通过重定向的磁盘传文件。Windows Server 、Windows 10/11 都连过，FreeRDP 那一类主机也能连。 **VNC**：noVNC ，VNC 的认证由后端做，浏览器拿不到 VNC 密码。 **Telnet**：给交换机、老设备用，自动填资产里存的账号。 **SSH 网关**：`ssh -p 2222 web-01@casvisor.example.com`，scp 、sftp 、rsync 、Xshell 、VS Code Remote 都能用，用公钥登录，权限和网页里是同一套。 **网域网关**：机器在另一个机房、或者在公司 NAT 后面，Casvisor 直连不到时，用一个 SSH 跳板机中转；连跳板机都没有的网络，可以在里面随便找台机器跑 `casvisor agent`，它主动连出来，不监听端口。 密码和私钥都是加密存库的，SSH 主机密钥和 RDP 证书首次连接时记下来，之后变了就拒绝连接。用户全程看不到服务器的密码。 ### 控制 权限按 用户 / 用户组 × 资产 / 资产标签 来配，动作有连接、复制、粘贴、上传、下载、端口转发，可以限来源 IP 段和有效期。用的是 Casbin 。 命令规则：正则匹配，命中就拦（不把回车发给目标机器，改发 Ctrl+C ）或只告警。网页终端和 SSH 网关都生效。 撤销立即生效：改权限、删权限、权限到期，已经连着的会话会被断开。 ### 审计 四种协议的会话都录像，回放就在浏览器里，用的是实时连接那套代码。SSH 和 Telnet 的录像还能下载成 asciicast 。 在线会话可以实时旁观，也可以直接断掉。 SSH/Telnet 的命令记录是从一个虚拟屏幕里读的，Tab 补全、上箭头调历史、中文、行内编辑都能记准； vi 、top 这种全屏程序里的回车和输密码不记。 文件传输和所有 API 改动都在操作日志里。 ### 运维 顺带做了补丁管理：SSH 资产可以扫描待装的系统更新，一键安装、重启。Windows 走 Windows Update 的 COM 接口，Linux 支持 apt / dnf / yum 。 ### 部署 ```shell docker run -d --name casvisor -p 19000:19000 -p 2222:2222 \ -v casvisor-db:/db -v casvisor-recordings:/recordings casbin/casvisor ``` 默认 SQLite + 自带账号，管理员口令打印在日志里，第一次登录后改掉。要 SSO 、MFA 、LDAP 、社交登录，接 Casdoor 就行； Casdoor 的用户组直接能用在权限里。 ### 老实说的部分 - 没有数据库代理（ MySQL / PostgreSQL 的网页连接和 SQL 审计）和 K8s ，JumpServer 社区版这两个都有； - 一个资产只有一组系统账号，没有多账号、自动改密、访问申请工单； - 没有资产树和批量导入，资产多了管理起来比较笨； - 录像只能存在本机目录，还不能放 S3 / OSS ； - 本地账号模式没有 MFA ，要 MFA 得接 Casdoor ； - 命令审计靠读虚拟屏幕，不是把键盘输入全录下来，全屏程序里的操作看不到。 在线演示： https://demo.casvisor.com （有一个假的 SSH 和一个假的 VNC 可以连） 文档： https://casvisor.org 代码： https://github.com/casvisor/casvisor Apache-2.0 ，欢迎 issue 和 PR 。
