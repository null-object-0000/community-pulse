> 项目地址： 在线体验： （推荐 Chrome / Edge） 开源协议：MIT 一句话介绍：EO2Weave 是一个完全跑在浏览器里的 AI agent 平台——授权本地文件夹后，agent 直接在浏览器内读写你的文件、执行 Python；装上配套 Chrome 扩展，还能按 WebMCP 标准调用网站暴露的工具。我们不收集任何数据（数据流向详见下方说明）。 为什么值得一试 现在的 AI 编程工具要么是 IDE 插件（得先装环境），要么要把代码传到云端。我们的思路是：浏览器本身已经是个足够强的 agent 运行时。 AI agent 直接读写本地文件夹：基于 File System Access API 显式授权，不装任何东西，打开网页就能让它改你的项目 支持 WebMCP 标准：配套 Chrome 扩展提供 WebMCP 工具发现——任何网站都能通过标准 API 把能力暴露成 agent 可调用的工具（「网站即 MCP server」），agent 自动发现并调用 agent 自带联网：扩展内置 websearch / webfetch，浏览器内 agent 也能查资料、抓网页；另有 Rust native host 提供本机磁盘与命令执行桥（可选安装） 本地优先存储：SQLite WASM + OPFS；Pyodide 在浏览器里跑 Python（pandas / numpy / matplotlib），数据分析全程本地 每次改动可回滚：agent 的每一步文件修改都有 inline diff、快照和一键回滚，敢让 AI 大胆改 Rust + WASM 加速文件操作；多代理协作早期探索中 数据与隐私（提前说清楚） 平台本身没有后端：你的文件、对话、配置全部存在浏览器本地（OPFS），我们没有服务器存储这些数据，也没有埋点上报 模型自带（BYOK）：在设置里填自己的 API key，支持 DeepSeek / GLM / Qwen / Kimi / MiniMax / 火山引擎，以及任意 OpenAI 兼容接口 需要如实说明：AI 请求由你的浏览器直连所选模型服务商，agent 读取的文件内容会经过该服务商的服务器、受其隐私政策约束——这点与所有云端 AI 工具相同；区别在于这些请求不经手我们的服务器，我们无法也无需接触 本地 Python（Pyodide）执行的数据完全不出浏览器 文档（双语文档，这里列中文入口）： 用户指南： 快速上手（5 分钟本地跑起来）： 架构总览： OPFS + SQLite WASM 存储方案： Rust + WASM 工作流： WebMCP 与页面外 MCP 服务接入（Figma / 插件 bridge）： 浏览器扩展（WebMCP / websearch / native host）： 适合谁 想让 AI 直接读写本地文件干活，但希望文件与工作数据默认留在自己电脑里、处理过程透明可回滚的人 关注 agent 与浏览器结合、WebMCP 生态的工程师——我们在 SQLite WASM + OPFS、Pyodide、Rust WASM、浏览器扩展三层桥接上踩了不少坑，架构文档全部开源，欢迎交流 站点打开即用。欢迎试用、提 issue、点个 star ⭐ 以下是浏览器扩展提供的侧边栏运行模式的相关截图： <img width="640" height="400" alt="Image" src=" / <img width="640" height="400" alt="Image" src=" / <img width="640" height="400" alt="Image" src=" /

> TextToTalk 是一个「文案 → 讲解视频」的自动化工具：粘贴一段文案或一个 URL，AI 先规划出可编辑的分镜大纲，再逐页展开成 PPT 式页面，配上解说、字幕和背景音乐，最后无头渲染导出 MP4。做一集 3 分钟的科普视频通常要过「写稿 → 做 PPT → 配图 → 录音 → 剪辑」五关，它把中间三步压缩成一次回车。 几个设计上的取舍： 大纲先行，而不是黑盒直出。 先流式流出全局大纲，每页的核心信息、版式、角色、节奏都可以增删、上下移、逐页修改；确认之后才展开分镜——在花时间渲染之前先把方向定对。 逐页重做，而不是整片重抽。 第 5 页不满意，可以单独重新生成，或就地编辑标题 / 解说 / 要点 / 时长 / 版式；改完自动作废旧成片，状态回到可再渲染。 零素材依赖，纯代码画一切。 背景音乐是纯 Node 数学生成的 WAV（琶音 + 低音 + 包络），没有任何音频素材；地图是结构化 SVG（标记点 / 航线 / 区域多边形），不调用任何在线地图服务；图表、图示、图标全是矢量绘制。 预览即成片。 分镜缩略图不是示意图，而是直接用服务端真实的 Remotion 场景组件渲染出来的，1920 设计宽等比缩放，看到什么就导出什么。 链接直接进，公众号也能抓。 贴 URL 自动抓正文，静态页走内置 fetch，JS 动态渲染的页面（公众号 / 知乎等）自动回退 Playwright 真浏览器。 桌面版开箱即用。 Electron 封装、内置 ffmpeg，设置面板配好 Key 就能用；也提供免安装包，整个文件夹拷进 U 盘带走。 画面侧由 16 个场景组件 + 26 条分发规则组成，根据页面字段自动匹配模板，不需要手动挑。三种运行方式：Docker 一键起、本地开发跑源码、Windows 免安装包解压即用（无需 Node、无需 Docker）。 已知限制：目前只支持 1920×1080 横屏；任务状态存在内存里，TTL 24 小时；渲染是逐帧 CPU 密集任务，长视频需要一点耐心。 MIT 协议，欢迎 Issue 和 PR。 仓库：

> fastalp：纯 Rust 自适应无损浮点压缩库 项目地址： Crates.io： API 文档： <p align="center" <img src=" alt="fastalp 浮点压缩算法全量性能与压缩比横向对比" width="100%" </p 项目简介 fastalp 是自适应无损浮点压缩算法（Adaptive Lossless FloatingPoint Compression, ALP）的高性能纯 Rust 工业级实现。专为时序数据库、列式存储引擎与向量数据场景设计，提供超高吞吐的压缩与解压能力。 传统浮点压缩算法（如 Gorilla、Chimp、Fpzip）在面对现代高吞吐分析时往往受限于逐比特位级操作与分支预测失败开销。ALP 算法通过自适应寻找十进制最佳幂次将浮点数无损映射为定宽整数（FrameofReference），结合位打包与极低异常率处理，完美释放现代 CPU 的 SIMD 矢量化与流水线吞吐。 核心性能指标与实测优势 1. 极致单核解压吞吐（55 ~ 77 GB/s） 单核纯寄存器 SIMD 矢量化解码吞吐达到 55 至 77 GB/s。在第三方时序基准评测（graupel）中，单核实测解码达到 252 Mpt/s，数倍于传统流式算法。 2. 高速端到端批量编码（6.1 ~ 23.1 GB/s） 批量端到端编码达到 6.1 至 23.1 GB/s（graupel 实测单核时序编码达到 122 Mpt/s）。 3. 高压缩比与真实数据集评测 在 ALP 论文收录的 31 个公开标准数据集测试中，平均压缩比达到 2.29x。 在真实气象水文浮点时序数据集中，实测落盘体积仅为 1.225 字节/点（压缩比达到 13.1x）。 4. 零额外堆分配（ZeroAlloc） 提供流式 compressinto 与 decompressinto 接口，支持调用方就地传入预分配切片缓冲区，消除内存分配开销并完美支持栈缓冲区复用。 5. 健壮保底机制（Raw Fallback） 内置针对极端高熵序列与随机噪声浮点的保护机制，当压缩无法获得收益时自动平滑回退，杜绝体积膨胀。 6. 纯 Safe Rust 与环境兼容 核心编解码模块采用纯 safe Rust 编写，零第三方运行时依赖，原生支持 nostd 与嵌入式环境。
