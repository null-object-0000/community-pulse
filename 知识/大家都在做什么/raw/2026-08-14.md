### 【开源自荐】ProofTask：让 AI 编码任务必须通过测试才能交付 👤 1074739572
> 项目地址：< 项目介绍 ProofTask 是一个面向真实代码仓库的自主编码执行器。我做它是因为发现， 复杂 AI 编码任务最大的风险往往不是模型不工作，而是模型做了很多修改后， 没有可靠地证明“需求真的完成了”。 ProofTask 把一个 Goal 拆成多个有依赖的 Task。每个 Task 都有 Given/When/Then 验收标准、真实 pytest selector、机器验证证据和错误记录。 模型说完成、Todo 全部完成，都不会让 Task 完成；只有绑定测试实际通过， 系统才会解锁下一个 Task。 核心亮点 1. 测试不能编造：系统先收集仓库现有 pytest 节点，规划模型只能从中 选择 selector，不能凭空写测试文件路径或验证命令。 2. 没有测试先补测试：找不到能证明 Task 的测试时，进入专门的测试 生成阶段，重新收集 selector 并做基线执行后才允许实现。 3. Task 以证据完成：验证会保存命令、退出码、selector、收集数量和 输出摘要；没有 exitcode = 0 的证据就无法完成 Task。 4. 复杂任务可控：Task 有显式依赖，失败固定回到当前 Task；Goal 和 Task 状态可持久化，支持暂停、恢复和取消。 5. 评估器不抢裁决权：独立 evaluator 可以检查覆盖和范围，但不能把 失败的机器验证改判为通过。 使用方式 text /goal verify "python m pytest q" 修复分页接口并补齐边界测试 verify 是全部 Task 完成后的全局回归命令；每个 Task 在执行过程中都会 运行自己的聚焦测试。 项目目前的目标测试为 8 passed，内置评估为 81 passed、0 failed。 <p align="center" alt="ProofTask Goal CLI: Task graph, test binding, and machine delivery gate" width="100%" </p <p align="center"<subGoal 执行时，模型的工作过程与机器是否允许推进会被明确分开。</sub</p 如果你也在尝试让 AI Agent 处理长链路代码任务，欢迎试用、提 Issue 或参与 讨论。尤其欢迎关于“验收标准如何映射到测试”的反馈。
