### [开源自荐] dsh-novel-craft：把作者的点选压成写作规律，只有规律进模型上下文 👤 shiyan688
> 安装：dsh plugin --profile web add dsh-novel-craft（npm dsh-novel-craft@0.1.4，MIT） 这是什么 给中文网文/小说创作场景做的一个「作者品味校准」工作台，是 DeepSeek Harness 的插件（宿主半区 + 浏览器半区）。 一句话：一轮生成若干"结构不同"的候选稿，作者只做一件事——在觉得好的段落上点一下、在别扭的段落上点一下。这些点选被压成可复用的写作规律，下一轮写稿照着收敛。 我遇到的问题（自己写了半年小说，都是真事） 1. 禁AI腔清单能让模型不像 AI，但做不到"像这个作者"。 清单人人都在抄，抄完模型不油腻了，可它依然不是我。 2. 作者的真实反馈从来不沉淀。 今天说"太刻意"，明天说"没网感"，第三轮同一个毛病。因为我给的是评价，不是可复用的写法。 3. 原文喂不进上下文。 那把作者选中的段落整理成档案交给模型？起步 6 KB，一轮一个样，模型还得自己从原文里猜规律——猜不准，还烧掉上下文预算。 做法：三层分离，加一条硬规则 硬规则是：进模型上下文的只有规律，原文永远不进。 | 文件（都在 <候选目录>/.dsh-novel-craft/） | 给谁看 | 进上下文？ | | --- | --- | --- | | marks.json | 工作台（机器可读的好/坏标注） | ❌ 永不 | | 证据摘录.md | 原文证据，给人回查、给提炼当输入 | ❌（文件头写着"不要读进写稿上下文"） | | 作者偏好档案.md | 写稿会话只读这一份（只有规律） | ✅ 就它 | 真机数字（不是估算） 在一份真实书稿上点 30 段好/坏（第 1、2、8 章） 点一次「提炼规律」：1.8 秒回来 14 条规律 作者偏好档案.md 从 6140 B 的原文摘录变成 714 B 的规律，里面一条原文都没有 下一轮写稿只需要读这 714 B 提炼出来的规律长这样（原样抄几条）： 喜欢： 器物先动，人后发声，用声响顶点收束静默 给反派一句极短的私人恐惧，落点在赔不起 避免： 不要用比喻堆砌写人群的恐惧 不要用旁白解释反应者的心理活动 规律是怎么来的（以及为什么不是全自动） 一次便宜的辅助模型调用把待提炼的原文压成条目，但条目不直接进档案——作者逐条勾选才采纳，水位随之前移，同一段不会被重复送。规律区是作者的，工作台维护的自动块之外永不被覆盖，单条规律可以一键删掉。 顺手记两个插件坑（可能对写 dsh 插件的人有用） 1. 插件行的 apply 可能早于服务挂载：在 0.1.6-alpha.1 上实测，同步 apply 里 ctx.get('webServer') 拿到的是 undefined——写成"取不到就 return"的插件会在新版本上静默什么都不做。改成 ctx.inject(['settings','webServer'], …) 等就绪（带超时兜底）即可。 2. 调模型做结构化输出要默认关掉推理：推理 token 和正文共用一份输出预算，我这边表现是"接口 5.6 秒返回、解析出 0 条规律"，关掉推理 + 抬高预算后 1.8 秒出 14 条（官方 Discussion #6857 也写了这条）。 3. 另外客户端 bundle 的下发地址从 /plugins/<id>/client.js 变成了组合脚本 /plugins/??a/client.js,b/client.js&rev=…——插件不用管，但拿裸 URL 做测试的人会误以为"插件没被收录"。 工程质量 209 项断言：静态守卫（Hook 顺序、词条完整性）+ 回环端口上的接口闭环（含假 LLM 的提炼链路）+ 用成对 react/react-dom 把客户端组件真渲染成 HTML；测试不依赖任何本机路径 scripts/check-dsh-compat.mjs + CI 矩阵：每周自动在 latest / next / alpha / 0.1.2-rc.1 四档上真装一份 dsh、起服务、验宿主路由与客户端半区下发 出处与致谢：skills/novel-writing 的禁AI腔清单改编自 dsh-novel-solo（MIT），平台 DeepSeek Harness（MIT），完整声明在 THIRDPARTYNOTICES.md 仓库里还带了两个配套 skill（taste-calibration / novel-writing），装到 .dsh/skills/ 即可，插件负责"让你低负担地点"，skill 负责"告诉 agent 怎么用这些标注"。

> 它解决什么问题 在 Java 里调第三方接口，通常要先从 Postman、Apifox 或浏览器 DevTools 复制一段 cURL，再手动翻译成 OkHttp 或 HttpClient 代码——构造请求头、拼参数、设超时、处理响应，一套下来几十行。等接口文档更新了，这段代码还得跟着改。 JQuick-Curl 的做法是：cURL 命令怎么写，Java 代码就怎么用。命令交给 ANTLR 解析，底层用 OkHttp 连接池执行，中间不需要手写请求构建代码。 一个例子 从 Postman 复制出来的命令是： bash curl -X POST \ H 'Content-Type: application/json' \ d '{"sku":"A-1001","count":2}' 在 Java 里直接贴到接口方法上： java public interface OrderApi { @JCurlCommand("curl -X POST " + "-H 'Content-Type: application/json' " + "-d '{\"sku\":\"A-1001\",\"count\":2}'") String create(JQuickCurlReq request); } OrderApi api = JCurlInvoker.createProxy(OrderApi.class); String body = api.create(new JQuickCurlReq()); 接口定义和业务代码是分开的。调试工具里验证通过的请求，复制过来就能跑。 API 管理：注解之外还有 XML 除了 @JCurlCommand 注解，也可以把接口集中写在 apis.xml 里，请求模板完全不进 Java 代码： xml <curls namespace="com.example.UserApi"> <curl name="getUser" returnClass="java.lang.String"> curl -X GET -b @./cookies.txt </curl> </curls> XML 里支持 #{name} 占位符和 <if test="..."> 条件渲染，配合 JQuickXmlFactory 生成代理客户端。注解方式用 ${name}，XML 方式用 #{name}，凭据可以从环境变量注入，不用硬编码。 调试相关的几个点 Cookie 会话：-c ./cookies.txt 把 Set-Cookie 按 Netscape 格式写盘，-b @./cookies.txt 下次请求自动带上，登录态可以跨调用保持。 文件上传下载：-F 'file=@./report.pdf' 支持多部分上传，--output './download/report.pdf' 直接把响应写入磁盘。 批量执行：JQuickCurlBatchRunner 扫描一个类里所有 @JCurlCommand 方法，按顺序跑完，返回结果列表。 拦截器与配置：JQuickCurlConfig 是全局单例，统一管超时、连接池、重试、重定向和拦截器，加 Token、打日志这类横切逻辑不用改业务代码。 已实现的 curl 选项：-X、-H、-d 系列、-b / -c、-F、-o、-u、-L、-x、--http2、-k、-v 等都有解析器和测试覆盖。 背景 项目由 Dromara 开源社区维护，已入选 Awesome Java 列表，目前 Apache License 2.0。Maven 坐标： xml <dependency> <groupId>io.github.paohaijiao</groupId> <artifactId>jquick-curl</artifactId> <version>2.5.0</version> </dependency> 适合需要频繁对接第三方接口、又不想为每个接口手写一套 HTTP 代码的 Java 项目。
