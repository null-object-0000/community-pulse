### 自荐 | Codex Co²：AI 时代的结对编程，应该是怎样的？ 👤 SpaceCoder-Kafka
> 重新搬回的“椅子” 过去，两个程序员想一起解决同一个问题，可以把椅子挪到同一块屏幕前。 一个人负责操作键盘，另一个人负责审视思路；遇到分歧，就停下来讨论。屏幕上的代码是两个人共同产出的成果，问题的来龙去脉，也在这一问一答中逐渐对齐。 这种协作的方法，就叫做“结对编程”。 如今，AI 俨然已经成了坐在我们屏幕另一侧的新搭档。 我们向它描述需求，让它阅读代码、分析问题，并尝试修改。在一轮轮对话之后，那条会话里逐渐积累起了整个任务的背景，包括：为什么要做这个功能，哪些方案已经被否定，还有什么约束必须遵守等等。 可当后续有另外一位同事想参与进来，或接手你的工作时，事情就变得开始低效了。 我们需要把对话截图发过去，把代码复制出来，再把同事的意见转述回给 AI。对方如果想追问一句，又要等我们把问题送进去，再把回答搬回来。 AI 明明已经能够参与越来越多的执行工作了，但人与人之间的协作，仍可能被这些来回的转述给拖住。 个人的生产力被放大了，团队掌握的信息，却未必能同样顺畅地汇集到一起。 是时候，我们该重新搬回那张“椅子”了。 Codex Co² 想解决什么？ 基于同一条会话的协作，正是我想用 Codex Co² 来解决的问题。 Codex Co² 的全称是 Codex Conversation Collaboration（Codex 会话协作），名字有点长，但是想做的事情很简单：让多个人参与同一条 Codex 会话，一起推进工作。 分享者可以继续在官方 Codex Desktop 中工作，只需在 Co² 里选中一条已有会话，生成邀请，发给协作者。协作者则通过浏览器打开邀请，申请加入；获准后，就能阅读共享上下文，向同一个 Agent 补充要求，并跟进它的回复。 协作者无需安装 Co²，也无需单独登录 Codex。发出的每一条消息，都会沿用分享者当前会话的工具、权限和额度。 邀请协作者 不妨看一个具体的例子。 假设有用户反馈：“任务已经处理完成，页面上的状态却一直没有变化，刷新之后才恢复。” 运营拿到 FeedbackID 后，可以先在 Codex 中分析相关的用户日志，得到初步结论：操作请求已经成功，问题可能出在页面状态的更新环节。 随后，运营就可以通过 Co² ，将这条会话分享给研发。 研发加入后，可以沿着已有的分析继续追问：服务端有没有发出状态变更通知？客户端是否收到？异常发生前，是否经历过断线和重连？ 结合日志与相关代码，问题逐渐收敛：客户端在网络重连后没有恢复实时订阅，后续状态变更因此未能到达页面；而手动刷新会重新拉取数据，所以显示又恢复了正常。 到这里，一条模糊的用户反馈，才有了可以解释、可以验证的技术根因。 邀请另一协作者 但找到根因，并不意味着就走到了解决问题的最后一步。 研发可以继续让 Agent 梳理修复方案：补齐重连后的订阅恢复，并在恢复连接时校准一次状态；同时整理受影响的场景、改动范围、验证成本，以及临时处理方式，再邀请产品加入这条会话。 产品看到的，便包括了用户最初遇到的困难、运营从日志中获得的线索、研发定位根因的过程，以及不同处理方式的成本与风险。 基于这些信息，产品可以决定是否需要立即修复、如何安排版本，以及在修复上线前怎样回应用户。 运营带来现场，研发追到根因，产品决定如何推进。 不同角色的判断，在同一条会话里逐步接续。前一个人留下的分析，成为后一个人继续追问的起点，最终把一条用户反馈推进为一个有依据的处理决定。 收集分散的信息 Co² 带来的这个看起来很小的变化，恰恰对应着软件开发中一个长期存在的事实：理解一个问题所需要的信息，往往分散在不同的人手里。 产品同事知道某条看似奇怪的规则，背后对应着怎样的业务现实；测试同事知道一个偶发问题，究竟要经过哪些步骤才能复现；熟悉系统的工程师则知道，一处看似无害的改动，可能牵动哪些历史约束。 这些判断，很难仅凭一句“帮我把功能做出来”就交代清楚。 AI 能够处理的信息再多，也需要有人把这些最相关的事实带到它面前。因此，当我们讨论如何更好地使用 AI 时，更值得考虑的是：怎样让那些真正了解问题的人，更容易参与当前的工作。 Co² 尝试提供的，就是这样一个入口。 我希望它能够用在结对开发中，让另一位工程师直接参与方案讨论；用在远程排障中，让了解现场的人补充复现条件；也用在需求澄清中，让业务上的判断及时进入实现过程。 还有更多可能性 当然，Co² 目前仍是一个早期的独立实验项目。 项目代码已经在 Github 上开源，提供了 macOS 和 Windows 安装包，可以通过 Homebrew 安装后打开，也可以直接在浏览器上运行。 使用时还需要理解以下几点限制： 共享会话沿用原来的执行环境和额度，协作者的每一条消息，实际都是以分享者的身份在发送的，使用时需要注意权限控制和额度把控。 公网分享经过中继，使用普通 TLS，没有端到端加密，记得只邀请可信任的协作者，或者开启“仅内网可访问”开关； 退出 Co² 时，分享出去的邀请链接会变成不可访问，因为 Co² 设计上就是服务于当下的协作，而不是作为一个长期的入口。 如果你也正在和同事一起使用 Codex，欢迎试用，并把遇到的体验问题通过 Issue 反馈给我，一起参与 Co² 的共创。 那些曾经需要截图、复制粘贴、反复转述的环节，就是 Co² 这个工具能帮你们改进的地方。 结语 希望，我们在用 AI 来提升我们工作效率的同时，也能继续给身边的同事留出位置。 让了解需求的人、熟悉代码的人、发现问题的人，都能把各自掌握的那一部分带进来，完成一个共同的协作，这才是团队存在的意义。 曾经屏幕前的那把椅子，值得再搬近一些。

### 测速 500 兆，打游戏照样卡。我做了个网站，专门查「卡在哪」 👤 yt1988
> ![]( https://i.v2ex.co/G1PKbH4d.png) 上个月，我的网卡得离谱。 打游戏延迟忽高忽低，开视频会议对面说我声音一顿一顿的，GitHub 拉个仓库能拉一顿饭的工夫。 打电话给运营商，客服很熟练：「您先测个速。」 测了，500 兆，满速。 「那就没问题哦。」 ……问题是，我缺的根本不是带宽。我卡在每点一下都要等，而测速网站从来不测这个。 ping ？浏览器发不了，好多服务也不回 ping 。查 IP 的网站呢？只告诉你一个 IP ，然后就没了。 查了一圈也没找到顺手的工具，那就自己写一个。 👉 **https://1ms.dog** 打开就开始测，什么都不用点。 一只柴犬从你的浏览器出发，跑去 40 多个常用网站「捡球」：视频、游戏、社交、开发工具、AI 、CDN ，再加上你所在地区最常用的几个（国内就是百度、B 站、微信、抖音）。**延迟越高，球扔得越远**，一眼就看出谁快谁慢。 ![]( https://i.v2ex.co/2461fpwn.png) ### 它不光告诉你多少 ms ，还告诉你问题在哪 这是我最想要的部分。它把「国内常用」和「海外服务」分开算： - 国内快、海外慢：是线路的问题，换个 Wi‑Fi 也没用 - 国内也慢：先别骂运营商，重启一下路由器，或者离它近一点 - 都很快：恭喜，你的网没毛病，卡的是对面 再往下，打游戏、视频通话、看视频、写代码分别能打几分，也都给你写好了。点一下「视频通话」，它会把参考的那几个网站高亮出来。结论有来源，不是拍脑袋给的。 ### 你的网，可能不止一个出口 很多人不知道，你家的 IPv4 和 IPv6 走的可能是两条完全不同的路，公司网络、双线宽带也常常有好几个出口。 它会同时问一圈分布在不同地方的检测点，把你所有的出口按运营商列出来：在哪个城市、哪家运营商、哪个 AS 。移到旁边的小「!」上，还能看到是哪几个检测点发现的。 ### 一个让我自己都吓一跳的坑 刚写好那会儿，有个服务永远是 700 多 ms ，我还以为是自己家线路太烂。 查下来才发现，测试地址打到的是人家的业务服务器，对面先慢悠悠算了 400 多 ms ，然后把我重定向到了人机验证页。 **测出来的根本不是网速，是对面后台的加班时长。** 后来我把每个测试地址都换成了「由离你最近的节点直接回应」的那种，那个服务一下就从 700 掉到了 100 出头。现在每天都有自动巡检在跑，哪家偷偷改了接口，第二天就能发现。 ![]( https://i.v2ex.co/4onB1x7A.png) ### 还有几个小东西 - **只测一个**：`1ms.dog/zh-cn/github/` 只测 GitHub ，连测 10 次，告诉你中位数、首次连接要多久、抖得厉不厉害 - **只测一类**：`/zh-cn/game/` 只测游戏，开黑前点一下，心里有个数 - **一键分享**：生成图片或链接，**不带 IP**，放心发群里 - **不收你的数据**：所有请求都是你的浏览器直接发出去的，网站本身就是一堆静态文件，你测了什么它一个字节都不知道 - **彩蛋**：快速连点狗狗 5 下 🐕 ### 开源，MIT https://github.com/yt1988/1ms-index 纯静态，一行 `npx wrangler deploy` 就能部署到你自己的 Cloudflare ，免费。 有 bug 、想加哪个网站，或者觉得它的结论不对，都欢迎提 issue ，回帖说也行。 最后，回帖晒晒你的狗跑多快？我的是 133 ms ，「小跑」，说好的 1ms 呢 😂
