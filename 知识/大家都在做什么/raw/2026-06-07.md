### 【推荐工具】AI 编码 Agent 在会议室连续喊了三次「Mission Accomplished」 👤 coolbeevip
> 最近我开始大量使用 AI 编码工具处理一些重复性的开发工作。 以前写代码的时候，人基本都坐在电脑前等结果。 现在不一样了。 很多任务交给 Agent 之后，我会直接让它在后台运行： 修改代码 修复问题 编写测试 重构模块 然后去做别的事情。 为了知道任务什么时候完成，我给完成通知设置了一个特别的声音。 《红色警戒》里的经典语音： Mission Accomplished. 效果非常好。 每次听到这个声音，我就知道 Agent 又干完了一件活。 直到有一天。 我离开工位去参加一个会议。 会议刚开始没多久。 突然。 会议室外面传来一声： Mission Accomplished. 我愣了一下。 心想： 谁还在玩《红色警戒》？ 过了几分钟。 又来一次： Mission Accomplished. 这次我感觉有点不对劲。 然后。 第三次： Mission Accomplished. 这时候我终于意识到： 那是我的电脑。 原来在我离开工位后，蓝牙耳机断开了连接。 而 macOS 按照默认逻辑，自动把音频输出切换回了内置扬声器。 与此同时，后台运行的几个 AI 编码任务陆续完成。 于是电脑开始认真地向整个办公室汇报工作成果。 Mission Accomplished. Mission Accomplished. Mission Accomplished. 那一刻，所有人都知道我的 Agent 今天工作很努力。 事后想想。 问题其实不在通知音。 也不在 AI Agent。 macOS 的行为完全符合预期。 耳机断开了。 系统总要找一个新的输出设备。 大多数情况下，它会切换到内置扬声器。 逻辑上没有任何问题。 但现实里并不总是这样。 很多时候，我们根本不希望声音继续播放。 例如： 在办公室 在会议室 在共享空间 深夜工作 离开工位时 后台运行长时间任务时 这些场景下。 突然外放不是方便。 而是尴尬。 于是我开始寻找解决方案。 我找到了一些音频路由工具。 找到了一些自动化工具。 甚至找到了一些需要编写脚本的方案。 但始终没有找到一个足够简单的工具。 我真正想要的功能只有一句话： 当耳机断开并切换到内置扬声器时，立即静音。 仅此而已。 既然找不到。 那就自己做一个。 于是有了 QuietSwitch。 它是一个运行在 macOS 菜单栏中的小工具。 当检测到： 耳机 → 内置扬声器 这个切换发生时， 立即自动静音。 避免任何意外外放。 没有账号。 没有云服务。 没有复杂配置。 没有数据收集。 只解决一个问题。 有趣的是。 我觉得这个问题未来可能会越来越常见。 随着 AI Agent 和自动化工具越来越普及。 越来越多的人会把任务交给电脑，然后离开工位。 而任务完成通知、语音提醒、自动播放内容，也会越来越频繁地出现在人不在电脑前的时候。 软件变得越来越智能。 但有时候。 我们需要的并不是更智能的软件。 而是一个简单的保险丝。 QuietSwitch 就是这样一个小工具。 它诞生于一次有点尴尬的会议事故。 但我始终相信。 很多好产品，最开始都只是开发者想解决自己的一个小麻烦。 项目地址： App Store：

### 【开源自荐】Tutti 是一个 macOS 菜单栏小工具，让你的多个扬声器同时播放同一段声音。 👤 BarryBarrywu
> Tutti 一个声音，响遍全场 Tutti 是一个 macOS 菜单栏小工具，让同一份声音同时从多个输出设备播放。 macOS 的系统音频一次只能播放一个设备，想边外放边戴耳机、或者让客厅和卧室两组音箱一起响，系统自带的音量功能做不到，需要去 MIDI 里进行设置。 Tutti 补上了这个缺口。不用装任何虚拟音频驱动，也没有内核扩展，全部用苹果自带的 CoreAudio 框架实现。在菜单栏勾选多个输出，Tutti 会临时搭一个聚合设备，让每个设备同时发声；退出时原来的输出干净恢复，不留后台进程，也不留垃圾设备。 使用场景 家里多台蓝牙音响，同时播放一首歌曲，每个房间的音乐同步。 一台 Mac 能同时连两副、甚至三副 AirPods。在咖啡馆不方便外放？你和朋友一人戴一副，一起看同一部电影、听同一首歌。 老师上课时，可以通过耳机监听自己的声音，同时让现场的观众和学生听到功放的声音。直播、录课同理：自己戴耳机听，声音照常外放。 任何"想让同一份声音同时去几个地方"的场景。 核心功能 多设备同步输出，在菜单栏勾选有线音箱、、蓝牙耳机、AirPods、显示器的任意组合，同一个声音同时播，完全同步。 音量控制，一个主音量统一调全组，每个设备还能单独调音量和静音。 蓝牙电量，连着的蓝牙耳机电量直接显示在面板里，不用再去系统里查。 替代系统音量图标，可以把 Tutti 设成菜单栏那个音量图标，按音量键时弹的也是它自己的 OSD。 快捷键增强，键盘音量键和滚轮直接控制整组输出，还能把常用的设备组合存成预设，一键切换。 主要能力 源码在 GitHub 上公开（PolyForm Noncommercial 许可）。支持 9 种语言，需要 macOS 13 及以上。 官网： Github：

### 【开源自荐】Scout4j：让 AI 编程助手先读懂 Java 后端项目，再动手改代码 👤 kyle641320
> Scout4j Scout4j 是一个面向 Java 企业后端项目的 AgentSkill，用来约束 AI 编程助手在修改代码前，先调查项目结构、读取本地约定、参考相邻实现，再制定计划、修改代码和验证结果。 项目地址： 现在很多人已经开始用 Claude Code、Cursor、Codex 等 AI 编程工具处理真实业务代码。但在 Java 后端项目里，AI 很容易犯一个问题：还没看懂项目，就直接开始改。 比如： 没看现有分层结构，就新建一套不一致的代码； 没看 mapper / repository 写法，就乱补 SQL； 没理解事务边界，就把逻辑拆错位置； 没确认 RPC / MQ / CDC / 下游依赖，就只改了表面代码； 没跑针对性测试，就给出“已完成”的结论。 Scout4j 想解决的就是这个问题：给 AI 编程助手一套 Java 企业后端工作的流程约束。 它会引导 Agent 按下面顺序工作： investigate → plan → edit → verify → summarize 也就是： 1. 先调查仓库结构和本地约定； 2. 再根据任务类型读取对应参考； 3. 然后制定修改计划； 4. 修改代码； 5. 最后做针对性验证和总结。 适用场景 Scout4j 覆盖了一些常见 Java 后端任务： 新增字段 / API / 数据库 schema； bug fix 和 code review； 事务边界和一致性问题； RPC / 下游依赖的超时、重试、失败传播； MQ / CDC 消费和投影更新； 数据修复 / backfill job； 分页、性能和 SQL / mapper 一致性； 单元测试、集成测试和验证策略。 特点 不绑定具体公司架构； 不默认假设 Spring Boot、Maven、MyBatis、JPA、Kafka 或 DDD，除非目标仓库本身体现这些模式； 重点不是“给出标准答案”，而是让 Agent 先读懂项目，再按项目已有风格改； 提供了若干细分参考文档，例如 RPC、事务、数据修复、性能、测试等； 包含一个轻量的 deoverfit 检查脚本，避免把私有 benchmark 或标准答案泄露进公开 skill； 测试阶段已在 100+ 个 GitHub 开源企业级 Java 项目上验证，对 Agent 的代码修改质量、上下文遵循和验证完整性有明显提升。 为什么做这个项目 AI 编程工具越来越强，但在企业后端项目里，真正危险的地方往往不是“不会写代码”，而是“没理解上下文就开始写代码”。 Scout4j 更像是给 AI 编程助手的一套工作纪律： 不要一上来就 patch，先 scout 一遍项目。 项目开源，MIT License。 GitHub：
