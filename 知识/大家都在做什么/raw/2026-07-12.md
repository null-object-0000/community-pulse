### 【工具自荐】Agent Skills Finder：安装前先看懂 agent skills 的目录站 👤 captainChaozi
> 最近 Claude Code、Codex、OpenClaw、Cursor 这类 agent 工具都开始支持可复用的 skills，但实际找 skill 还是比较分散：很多内容藏在 GitHub 仓库、README 或个人项目里，安装前也不容易快速判断它到底做什么。 我做了一个目录站：Agent Skills Finder 它主要解决三个问题： 1. 按任务、分类、标签和关键词搜索 agent skills，不只是搜仓库名。 2. 进入详情页后，可以先看 SKILL.md、文件树、安装命令、作者、收藏、评分和评论，再决定要不要安装。 3. 登录后可以收藏 skills、创建 workflow collections，也可以提交 GitHub 仓库、skill 目录或 SKILL.md URL。 目前公开目录里已经有一批 Claude / Codex / OpenClaw / Cursor 等方向的 skills，首页、热门、新增、分类和合集都可以直接浏览。 这个站不是官方 marketplace，也不替代安全审计；第三方 skill 仍然建议安装前自己检查源码和说明。它的定位更像是一个安装前的发现和评估层，帮用户少翻一些分散的 GitHub 页面。

🔗 [官网](https://agentskillsfinder.com/) · [投稿页](https://github.com/ruanyf/weekly/issues/10674)

### 【开源自荐】LLM Wiki Agent Memory：让 Codex / Claude Code 拥有本地工程记忆 👤 miniLV
> 项目地址： 这是一个本地优先的 AI 编程记忆项目。它把 Codex 和 Claude Code 的本机会话整理成可查询、可审计的 Obsidian 风格 Markdown Wiki，让 Agent 在后续任务中找回历史决策、调试过程和防踩坑经验。 项目不依赖向量数据库或云端记忆服务，采用 Capture → Daily → Reconcile → Retrieve 的分层流程：先保留原始证据，再生成每日整理，周期复核后才晋升为长期经验，从而减少 AI 对自身历史回答的重复强化和记忆污染。 主要特点： 同时支持 Codex 与 Claude Code 本地 session 数据保留在本机，记忆是可以直接阅读、编辑和 Git 管理的 Markdown 提供本地 Web 配置页，引导完成数据源和 Codex App Automations 配置 可从其他工程通过只读 skill 查询旧决策和调试上下文 无需向量数据库、账号或托管服务 快速体验： bash git clone cd llmwikiagentmemory bash scripts/configui.sh open 如何使用 配置完成后，在任意业务 repo 里直接对 Codex 说： text 使用 $engineeringmemoryloader 查询： 上次 configui 的 8765 端口冲突是怎么解决的？ Codex 会从本地 Markdown Wiki 返回相关日期、结论和关键证据；没有记录时明确返回 NOMATCH。 Codex 中查询工程记忆 Wiki Agent Memory 演示 Wiki Agent Memory 架构图 v0.1.0 Release：
