### 【开源自荐】Rclaude：共享 agent 的"使用"而不是 API —— 代码留本地，agent 在远端跑 👤 flyingEirc
> 【开源自荐】Rclaude：共享 agent 的"使用"而不是 API —— 代码留本地，agent 在远端跑 项目名称：Rclaude（flyingEirc/Rclaude） 项目简介：一套"远程文件访问 + 远程 agent 终端"系统。它不是把某个 agent 的 API 包装后转卖，而是共享 agent 的使用本身：一个已登录的编码 agent（Claude Code、Codex 等）跑在远端机器上，你在本地把工作区和终端接上去，直接驱动它——而你的代码始终留在自己机器上，不上传。 项目地址： 分类：AI Agent / 开发工具 核心亮点： 共享的是"使用"不是 API：终端直连真实 agent 二进制的完整 TUI 与 agentic loop。你共享出去的是"用这个 agent 这件事"。 代码不出本地：通过 FUSE 把本地工作区映射到远端，agent 用普通路径（cat/grep/ls/sed）读写你的项目；源文件始终在你机器上，server 只持有缓存与元数据，不保存完整副本。 daemon 主动外连：连接从你的机器发起到 server，server 无需反向拨回你的内网。 会话被收口到单一 agent：落点直接是命令行声明的 agent——整个会话离不开 agent 界面，也无法在 server 上乱逛。共享的是"这个 agent"，不是"一台 Linux"。 可选增强：前置 Caddy 终止 TLS（server 二进制保持明文 h2c）。 推荐理由：现在要么是分发 API key（拿到的是原始接口，不是 agent 的交互式使用），要么是把代码传到一台共享云机器上（代码交了出去）。Rclaude反过来：共享的是一个已登录 agent 的交互式使用，代码留在本地，适合小团队想摊薄一个订阅席位、又不愿把代码交出去的场景。Go 实现，server 端需 Linux + FUSE；目前 Codex / Claude Code/ Cursor Agent的 TUI attach 与远端执行全链路已跑通。仍是最小可用路径、非生产发行版，处于迭代中。

### 【开源自荐】murPick（知选）——把 AI 产品调研变成可勾选的"点菜菜单" 👤 ymustc

### 自荐软件:hevc.js — 236KB 的 WASM HEVC 解码器,让不支持 H.265 的浏览器也能播放 👤 privaloops
> 项目地址: README) 在线演示: hevc.js 是一个完全从 ITUT H.265 规范(716 页)从零写起的 HEVC 解码器, C++17 实现,编译为 WebAssembly 后只有 236KB(约为 libde265 WASM 版的 1/8), MIT 协议,零依赖。 它解决的问题:Windows 上的 Chrome 没有 HEVC 软解回退(旧显卡直接放不出来), Edge/Firefox 需要微软商店的付费扩展,Linux 看运气。hevc.js 通过拦截 MediaSource,在 Web Worker 里把 HEVC 实时转码为 H.264(WASM 解码 + WebCodecs 编码),让 dash.js 和 Shaka Player 在这些环境下正常播放 HEVC 流 —— 播放器完全无感知,一行 attachHevcSupport() 接入,不需要 COOP/COEP 响应头。 几个数字:1080p 解码 60fps(单线程),转码约 2.5 倍实时,与 ffmpeg 在 128 个测试码流上逐像素比对验证。已被 dash.js 官方收录为 playback sample(5.2.1+)。 比较特别的一点:它带有"算力感知 ABR"—— 弱 CPU 上转码跟不上实时时, 自动通过播放器自己的公开配置降低码率档位,避免缓冲区被掏空(带宽型 ABR 看不到 CPU 瓶颈)。
