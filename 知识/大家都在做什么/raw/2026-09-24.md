> 做了一个面部评分站 face-rating.net：模型在浏览器本地跑，照片全程不出设备，求拍砖 链接： https://face-rating.net ## 这是什么 一个面部评分工具。一张正面照，浏览器里的图像模型给一个 10 分制的分。不用注册、不用邮箱，**照片不上传**。目前全站免费，没有付费墙，也没有订阅。 ## 分数是怎么来的 1. 浏览器里的关键点模型先测出 478 个面部关键点（ MediaPipe Face Mesh ，468 点 + 10 个虹膜点）。**这一步不出分数。** 2. 用眼睛的位置把照片摆正、裁到脸部，裁剪时不拉伸五官。 3. 一个**本地**图像模型读裁剪图，再读它的**镜像版**，两次预测取平均，换算成 10 分。 4. 这个模型是在**人类照片评分数据**上训练的——所以它输出的是学到的偏好，不是普世审美标准。这点我写在页面上了，不想含糊过去。 ## 几何读数是另一回事，不参与评分 同一批关键点还能算出对称性、纵向横向间距、脸型、眼角角度。很多人以为这些是分数的「成分」，**不是**。分数来自图像模型，几何来自关键点，两者不相乘也不相加。页面上和 FAQ 里我都逐个说明了。 ## 「本地」具体是什么意思 模型文件跟页面一起下载，照片和所有中间产物都在浏览器内存里——不上传、服务器没副本、刷新就没了。网站上没有任何一条上传照片的路径。隐私政策里写明：不用你的照片训练模型、不出售面部数据、不把照片或分数给广告方；站上第三方只有 Cloudflare （托管与安全）和邮件服务商。 ## 现在免费的都有什么 - 10 分制评分 - 六项单项工具：Golden Ratio Face Calculator 、Face Shape Detector 、Canthal Tilt Test 、Face Symmetry Test 、Jawline Rating 、Recessed Chin （最后一个用侧脸照） - 一篇 guide：Asymmetric Face （不对称脸的原因、哪些偏方没证据、怎么自己量） - 结果能存成一张本地生成的卡片，分享与否你自己定 ## 我刻意没做的几件事 - **不发布平均分、不发布百分位。** 免费分数我根本不收集，也没有有代表性的样本，说你比 X% 的人好看只能说明我测了谁。 - **不说这是医学、皮肤科或心理判断**，也不建议用它决定要不要面诊。 - **不鼓励跨工具比分数。** 不同工具测的可能不是一个量，你上传的多半也不是同一张照片——照片条件带来的差异往往比工具之间还大。 - 黄金比例那套「美不美」的说法在学术上争议很大，页面上引了四篇论文（含 2024 年那篇质疑它的），出处都放出来你自己判断。 ## 已知局限 - 正面照测不准下巴和鼻子的前后突出度，那两个需要侧脸照——2D 的硬限制。 - 同条件下可复现；**换了光线、表情、相机距离数字就会变。变的是照片，不是你。** - 首次打开要下模型，会等几秒，这也是我最想知道体验好不好的一点。 ## 想听什么 - 首次加载模型多久？手机上能忍吗？ - 分数出来后你会不会想知道「这数是怎么算的」——上面那段讲清楚了吗？ - 结果页是不是信息过载？ - 哪个几何读数对你真有用，哪个是废话？ 拍砖随意。要说「这玩意儿助长容貌焦虑」——这个批评我接，所以百分位、排名、平均分我都砍了，分数也不留在服务器上。有更好的做法欢迎提。

章节标题及它在整条故事线中的作用； - 页面实际显示的文案； - 一个主画面事件，以及必须出现的人物、道具； - 构图、景别和镜头运动方向； - 文字放在左、右还是底部，为什么； - 从上一章进入本章的方式； - 从本章离开时，镜头停在哪里，怎样连接下一章。 先找出最容易发生跳切、人物变化或空间关系不成立的位置， 给出具体调整建议。 比如独眼巨人洞穴这一幕，如果主角在左侧、巨人在后方，文字就可以放在右侧相对空的区域，离开洞穴时，可以让镜头朝洞口光线推进；下一段如何接入海面，要在分镜阶段说明方向和中间经过什么。 # 5. 用少量样图确定风格，再固定人物设定 人物一致性需要单独写，尤其是有主角贯穿的故事。只重复角色名字是不能充分约束生成结果的！！ 以案例中的主角为基础，可以写一个固定的角色设定块，prompt 是： ``` 主角统一设定： 成年男性，深色中长卷发，短须，体格结实。 穿暗红色披风、青铜色胸甲、深蓝色短衣，佩戴皮革绑带。 脸部轮廓、发型、胡须长度和服装主色在各场景中保持一致。 允许因旅途出现湿水、尘土或轻微破损。 这个设定是本项目的视觉设计；需要换装的剧情节点另行标注。 生成时优先使用已经确认的角色参考图。 再把风格设定和本章画面分开写，后续修改会容易很多： 统一风格： 古希腊史诗插画，细腻绘画质感。 主要材料为青铜、粗布、木材、岩石和海水。 暖金色自然光与深蓝色阴影形成对比，保留清晰的前中后景。 沿用已确认的人物参考，不重新设计主角。 画面内不生成文字、Logo 、水印或现代物品。 本章画面： 特洛伊战后的海岸。主角站在木船前部，回望远处冒烟的城池。 前景有船舷与绳索，中景是主角，背景是海面与城市。 主角偏右，左侧留下可放标题和两段正文的空间。 关键人物保持在手机裁切仍能看见的安全区域。 ``` 样图不合适时，修改意见也尽量具体： 保留目前的色调、绘画质感和光线。 第二张的主角脸型变窄、胡须变短，请按第一张参考统一。 第三张主角太靠边，请移向画面中央一些，避免手机竖屏裁掉脸。 第一张左侧准备放正文，请减少该区域的高亮烟雾和密集细节。 # 6. 网页阶段，把镜头进程、文字和滚动关系调好 有了素材，网页还需要解决几个问题：停在某一章时文字能否读完，转场时文字何时退出，手机上主体有没有被裁掉，以及视频加载失败时页面显示什么。 《奥德赛》案例里，文字位置随构图变化：有些章节在左侧，有些在右侧，结尾落到下方。规划时就应该把这件事交代给 Agent 。 可以这样提出网页制作要求： ``` 请按已经确认的分镜和素材组装网页。 所有场景放在同一个固定全屏舞台里。 滚动进度映射到场景与连接镜头的时间线，支持向上回看。 每章的完整文案同时出现，让用户可以停下来阅读。 连接镜头期间隐藏正文，下一章进入后再显示对应文案。 文字位置按分镜安排，不遮住脸部、手部动作和关键道具。 用局部柔和渐变改善对比，保留画面的可见范围。 提供章节导航、总进度，以及视频尚未加载时的静态封面。 手机端重新检查裁切和文字位置。 系统启用减少动态效果时，保留可以阅读的静态版本。 正文与章节配置保存在 content/story.json ，方便后续修改。 素材也需要统一规格。Skill 会用 FFmpeg 处理尺寸、帧率、编码、时长等，并为网页按进度定位视频做准备。视频能正常播放，只能说明素材可用；滚动前进、后退时是否顺畅，还需要在页面里检查。 这里还有一个容易混淆的地方：视频时长和读者停留时间是两回事。页面把滚动进度映射到视频位置，读者可以停下来读文字。如果感觉某章一滚就过去了，应该检查这一章分配的滚动距离和文字出现区间，再决定是否调整素材。 ``` 项目生成后，常用的本地检查和预览命令是： ``` python scripts/verify_media.py . python scripts/contact_sheet.py . python scripts/serve_project.py . --port 8080 ``` 这些命令在生成后的项目目录中运行。第一个检查素材规格，第二个生成便于横向查看的画面总览，第三个启动本地预览。也可以让 Agent 执行并解释检查结果。 返工时，最好指到具体章节和具体问题。比如： ``` 第二章人物没问题，但标题压到了洞口的亮部，正文不好读。 先调整文字位置和局部渐变，保留当前素材。 第三章进入第四章时，前一个镜头向前，后一个突然向左，接缝很明显。 请检查这两段实际边界帧，提出新的连接路线，先给我看方案。 第五章手机端把主角的脸裁掉了。 请先检查视频的显示位置；如果原始构图没有调整空间， 再说明需要重做哪张图、哪段视频，以及受影响的相邻连接镜头。 ``` 写作不易，希望大家支持！
