### 【开源自荐】AKM：智能体在执行任务前先把用户画像挖出来（含 SSRN 论文与可复现实测） 👤 sirsws
> AKM (Active Knowledge Modeling) 是一套面向 AI 智能体的上游方法：在智能体执行任务之前，先主动挖掘用户的目标、约束、偏好、风险边界、决策风格，整理成结构化用户画像，再沉淀到智能体的上下文承载面（USER.md / SOUL.md / Custom Instructions / Memory）供任意下游智能体反复加载。 项目地址： 中文 README： 为什么做 AKM 现在大多数智能体平台（GPTs、Gems、Claude Project、OpenClaw）都已经提供了上下文承载面——instructions、memory、profile、AGENTS.md。但用户面对一个空白的 instruction 框时，其实并不知道应该写什么。 最后常见的结果是：写一堆性格描述、塞几条偏好、复制一段提示词模板，用了一阵发现智能体还是给"提升核心竞争力""注意基础款""每周练五天加有氧"这种正确但无用的建议。 问题不是"模型不强"，也不是"提示词不够长"，而是根本没人系统地把用户挖清楚过。 AKM 想补的是这一步：承载面有了，方法论缺位。 AKM 的两步架构 第一步：画像挖掘 一段标准化的挖掘对话，把用户的目标、硬约束、偏好、资产、风险边界、决策风格系统问清楚，产出结构化用户画像（不是建议）。 第二步：画像复用 画像写进 USER.md / SOUL.md / Custom Instructions / 自建智能体的 system prompt。之后任意下游智能体在执行具体任务前都会先加载这份画像。挖一次，多个智能体反复使用，跨会话有效。 这是 AKM 和"会先反问几句的 GPT"的根本差别：后者每次新会话重问，画像不沉淀；前者画像作为基础设施被反复调用。 三个落地分支 DaE（DialogueasElicitation）：个人顾问场景，AKM 的第一个完整实现。论文已在 SSRN 发表：《Reducing Alignment Debt in AI Advisory: The DialogueasElicitation Approach》 Fitness：训练与恢复决策，处理伤病、可用时间、器械等真实约束 Fashion：衣橱、场景与采购决策，处理身材、资产、预算等真实约束 每个分支都附 skill 包，可直接装到 Claude / OpenClaw。 可复现实测工具包 仓库内附 AKMBenchmarkToolkit，开源所有代码、提示词、合成画像、评分规则，本地可复现： 在 10 个合成用户画像上对比四组条件（无画像 / 自然语言碎片 / AKM 结构化画像 / AKM 挖掘后画像），AKM 组在约束命中、风险控制、取舍意识等维度稳定高于其他组。这不是临床实验，只说明在结构化输入条件下，智能体对硬约束和风险的处理显著改善。 当前状态 母方法、母论文、三个分支落地、可复现 benchmark 工具包、双语 README 全部就绪 后续会扩到 30 个合成画像规模并加入第二个 judge 模型 欢迎 builder 拿去做对比实验，或基于自己的场景建分支 License: Apache 2.0

> 项目地址： 一句话： 给 LLM Coding Agent 准备的Chrome浏览器控制工具 —— 直接通过CDP协议连接现有Chrome，无需MCP中间层，一个命令一次操作，输出轻量结果。加上智能页面锁定和持久化守护进程，Token消耗仅为传统方案的百分之一。 🚀 亮点 1. 真正为 AI Agent 设计的工作流 问题：MCP 式的浏览器工具会把每一次交互的完整协议载荷都塞进上下文，一个截图能吃掉几千 token，且每次都要重新连接。 解决：chromedevtools 直接与 Chrome 的 DevTools 协议对话，一次连接（守护进程保持），一条命令输出一条结果。没有多余的中间层，没有重复的握手开销。 bash 第一次导航，拿到友好锁定名 chromedevtools navigate [target:redsnake] 后续所有操作通过 target 永久锁定该标签页 chromedevtools target redsnake snapshot chromedevtools target redsnake fill "email" "user@example.com" chromedevtools target redsnake click "submit" 为什么比 MCP / Puppeteer 更省 Token？ | 方案 | 每次操作 Token 开销 | 连接方式 | 页面锁定 | ||||| | chromedevtoolscli | 仅命令+结果文本（~100 token） | 持久化守护进程 | 确定性 word‑pair | | MCP Server | 完整 CDP JSON‑RPC 封装（~2000+ token） | 每命令建立新 WS | 需维护会话状态 | | Puppeteer/Playwright | 启动独立浏览器 + 协议日志（~5000+ token） | 每脚本新实例 | 依赖代码变量 | 2. 守护进程 —— 零打扰、自动恢复 智能启动：第一次调用自动拉起后台守护进程，通过 Unix Socket 通信，后续命令无感复用。 绕过 macOS 防火墙弹窗：守护进程先绑定 socket，再惰性连接 Chrome —— 用户不会在每次启动时看到“允许传入连接”对话框。 崩溃自愈：若 Chrome 崩溃或 WebSocket 关闭，守护进程自动退出，下次调用重新建立，无需手动干预。 空闲退出：5 分钟无命令自动清理退出，不留僵尸进程。 3. 更稳健的表单交互 原生支持 <select 下拉框：fill 命令可直接按显示文本或 value 选中选项。 原生支持 checkbox / radio：传 "true" / "false" 字符串即可切换状态。 全局弹窗拦截：检测到 JavaScript 的 alert/confirm/prompt 未处理时，命令会立即失败并给出明确错误，避免永久挂起。evaluate 子命令新增 dialogaction accept/dismiss/text 用于自动处理弹窗。 坐标级点击：clickat <x <y 用于 Canvas 或无选择器场景。 4.
