### [【开源自荐】anti-vibe-writing：去除 AI 写作味，让你的AI文案倍儿地道的 Agent Skill](https://github.com/weijt606/anti-vibe-writing>) 👤 weijt606
> 【开源自荐】antivibewriting：去除 AI 写作味的 Agent 写作技能 项目地址：< antivibewriting 是一个用于去除“AI 写作味”的开源 Agent 写作技能。 现在很多人已经习惯用 AI 起草文章、帖子、README、产品文案、技术文档或内部报告。但 AI 生成的文字常常有一种很明显的模板感：过度分点、满屏 Markdown、空泛总结句、咨询腔、翻译腔、破折号滥用，以及那种“看起来很完整，但不像真人写的”的味道。 这个项目想解决的就是这个问题。 它不是一个单纯的 prompt 集，也不是所谓“AI 检测绕过工具”，而是一套可以接入 Agent 工作流的写作风格校正层。Claude Code、Codex 或其他 Agent 先完成初稿之后，再由它做最后一遍清理：在尽量不改变原意和事实的前提下，去掉明显的生成式痕迹，让文本更自然、更干净、更像人写的。 项目目前支持中英文，并针对两种语言分别整理了常见的 AI 写作痕迹。 中文部分重点处理： “赋能、打通、沉淀、抓手”等模板化表达 “首先、其次、最后”式机械分层 “不是……而是……”式 AI 常用对仗 欧化句式和翻译腔 过度四字词、过度总结、过度升华 明显不像真人会在社交平台上写出来的句子 英文部分重点处理： generic AI tone templated phrasing overstructured Markdown fake balance corporate / consulting voice em dash overuse Reddit / forum 场景里容易被看出 AI 痕迹的表达方式 它的一个特点是：不只做“变口语化”，而是区分不同写作场景。 目前内置了几类场景预设： X / Twitter 微博 / 中文短帖 Reddit / 英文论坛评论 博客 / Newsletter / 公众号 播客 show notes / 视频脚本 README / 产品文档 技术备忘 / 内部报告 / 提案 不同场景的目标不一样。社交媒体要像真人随手发，README 要清楚但不堆格式，技术备忘要保留判断和密度，Reddit 评论则要更像一个人在认真帮忙，而不是 AI 账号在回答问题。 另一个比较有意思的点是，它提供了三种声音模式： 1. 默认干净模式 适合大多数文档，只做去模板、去冗余、去 AI 腔。 2. 人味儿质感模式 适合个人博客、创始人笔记、社交媒体。会在合适的位置保留一点真人写作的节奏，比如短句、残句、语气转折，但不会故意制造错误。 3. 学习模式 可以根据用户提供的真实写作样本，提取一份可复用的 host profile，让后续文本更接近某个具体作者的声音。 我觉得这个项目的核心价值在于：AI 写作越来越普及之后，“会不会生成”已经不是问题，“生成之后像不像人写的”开始变成问题。尤其是中文内容里，AI 痕迹非常容易被看出来。很多时候不是观点不对，而是语言太像系统组装出来的。 antivibewriting 把这些经验整理成了一套可以复用、可以迭代、可以放进 Agent 工作流里的规则。 它本质上是一套 Markdown 规则文件，不绑定具体平台。可以 clone 仓库使用，也可以直接把 SKILL.md 和相关 references 放进自己的 Agent 上下文、项目指令或自定义 prompt 里。 项目采用 MIT 协议开源，欢迎试用和提建议。


### [【开源自荐】TUI-easy-past：清理从终端 / TUI 复制出来的乱码式文本，一个指令让TUI文案粘贴更简单](https://github.com/weijt606/TUI-easy-past>) 👤 weijt606
> 【开源自荐】tep：清理从终端 / TUI 复制出来的乱码式文本 项目地址：< tep 是一个很小的命令行工具，用来清理从终端或 TUI 程序里复制出来的文本。 现在很多开发者开始在 Claude Code、Codex CLI、lazygit、vim、fzf、htop 这类终端界面里工作。但从这些界面里复制内容时，经常会遇到一个很烦的问题：粘贴到 X、Reddit、GitHub Issue、文档或聊天窗口之后，文本格式全乱了。 常见情况包括： 每一行前面都带着 TUI 的缩进 原本一段话被终端硬换行切成很多短行 表格、边框、竖线、框线符号一起被复制出来 ANSI 颜色控制符混进文本 Markdown 结构被破坏 代码块和普通段落混在一起，粘贴后很难读 tep 解决的就是这个小痛点。 它的使用方式很简单：在 TUI 里正常复制文本，然后运行 tep。它会读取系统剪贴板，自动清理内容，再把清理后的文本写回剪贴板。之后直接粘贴到任何地方即可。 这个工具比较适合经常使用 Claude Code、Codex CLI 或各种终端工具的人。比如你在 Claude Code 里复制了一段回答，粘贴到 GitHub Issue、X、Reddit 或文档里，原本经常会出现一堆断行和缩进；现在只需要运行一次 tep，就可以得到干净的文本。 它的一个特点是会自动区分 Markdown 和普通文本： 普通文本：自动把终端硬换行重新合并成自然段落 Markdown：保留标题、列表、引用、表格、代码块等结构，只修复被终端折行打断的正文 代码块：尽量原样保留，不随便重排 边框和 TUI chrome：自动剥离 ANSI 转义符：默认清理掉 它不是一个复杂的大工具，而是一个很典型的“每天可能用好几次”的开发者小工具。尤其是在 AI coding agent 变成日常开发入口之后，很多内容都从终端窗口里产生，再被复制到网页、文档和社交平台。tep 相当于给这个复制粘贴链路补了一层清理器。 安装方式： go install github.com/weijt606/TUIeasypast/cmd/tep@latest 常用方式： tep：清理剪贴板并写回 tep dryrun：只输出清理结果，不修改剪贴板 tep explain：显示它检测到了什么、改了什么 tep markdown：强制按 Markdown 处理 tep plain：强制按普通文本处理 tep norejoin：只清理边框和缩进，不合并换行 项目使用 Go 编写，没有第三方依赖。macOS 可以直接使用系统自带的 pbcopy / pbpaste，Linux 支持 wlcopy、xclip、xsel，Windows 使用系统剪贴板命令。 我做这个项目的原因是：TUI 工具越来越多，AI coding agent 也越来越多，但“从终端复制到外部世界”这个动作仍然很粗糙。tep 想把这个小摩擦磨平。 项目采用 MIT 协议开源，欢迎试用和提建议。

> 项目地址 类别 JS 项目标题 妙幕：本地媒体创作工作台，字幕生成、翻译、校对、烧录 项目描述 妙幕（SmartSub）是一款本地优先的桌面应用，帮你一站式完成「音视频转字幕 → 翻译 → 校对 → 合成」。所有转写都在本地完成，无需上传文件，隐私无忧；支持批量处理与 GPU 加速，可在 Windows / macOS / Linux 上运行。 支持 whisper.cpp、fasterwhisper、FunASR、Qwen3ASR、FireRedASR、以及本地 Whisper CLI 多种引擎 支持多达 17 家翻译服务商以及兼容OpenAI的ai服务商 亮点 1. 6 大 ASR 引擎自由切换，中文场景针对性拉满 打破了绝大多数本地字幕工具「只依赖 Whisper 系列」的同质化局限，原生集成 whisper.cpp、fasterwhisper、FunASR、Qwen3ASR、FireRedASR 5 种引擎，还支持调用用户自行安装的本地 Whisper CLI。 其中 FunASR、FireRedASR 均为中文识别表现更优的专项模型，对中文语音、方言（粤语）场景的识别精度显著优于通用 Whisper 模型。所有引擎都做了开箱即用封装：FunASR 等通过 sherpaonnx 原生库运行，fasterwhisper 自带独立 Python 运行时，用户无需手动配置开发环境，在应用内即可下载管理。 2. 全显卡厂商 GPU 加速，真正零门槛启用 这是同类工具中少有的「全场景加速」方案，彻底解决了非 N 卡用户只能纯 CPU 跑转写的痛点： NVIDIA 显卡支持 CUDA 加速，覆盖多个主流版本 AMD / Intel 显卡新增 Vulkan 后端，Windows/Linux 平台均可硬件加速 macOS Apple 芯片原生支持 Core ML / Metal 加速 同时做到了用户零配置：软件自动识别显卡型号、自动下载对应加速包、加载失败自动回退 CPU，无需手动安装 CUDA Toolkit 等复杂依赖。 3. 真正的全链路一站式闭环，无需跨工具跳转 从音视频导入到最终带字幕的视频输出，全程在单一软件内完成，覆盖完整工作流： 上游：多格式音视频批量转写、外部字幕文件导入 中游：17 种翻译服务、AI 一键润色、逐句对照视频的专业校对台 下游：硬字幕烧录 + 无损软字幕封装，支持字体、字号、颜色、描边、阴影、九宫格位置等全量样式自定义，搭配所见即所得实时预览 省去了用户在「转写工具 → 翻译工具 → 字幕编辑器 → 剪辑软件」之间反复切换的成本。 4. 翻译系统高度可定制，自由度远超同类 内置 17 个翻译服务，覆盖百度、谷歌、腾讯等传统机器翻译，以及豆包、DeepSeek、通义千问、Ollama 本地模型等大模型方案，兼容所有 OpenAI 格式的自定义接口。 更具差异化的是界面化自定义参数能力：用户无需修改代码，直接在图形界面中为每个翻译服务配置请求头、请求体参数，支持字符串、数值、布尔、数组等多种数据类型，还支持配置导入导出，高阶用户可以精细控制翻译效果，这在字幕工具中非常罕见。 5. 产品化完成度高，中文用户体验友好 摆脱了多数开源工具「功能堆砌、交互粗糙」的通病：采用任务式启动台设计，功能分区清晰，自带新手引导、命令面板、快捷键系统、任务活动中心；针对国内用户做了大量本土化优化，支持国内镜像源下载模型、夸克网盘安装包、Homebrew 一键安装，降低了国内用户的使用门槛。 示例代码 markdown 截图或演示视频 主界面 <img width="2560" height="1800" alt="Image" src=" / | 视频合成（字幕烧录） | 字幕校对 | | | | | !merge | !proofread |
