### 【开源自荐】ARTEX — AI 自主渗透测试系统 👤 Autumn-27
> ARTEX — AI 自主渗透测试系统 项目地址： 在线 Demo： <img width="2516" height="1222" alt="Image" src=" / ARTEX 是一个开源的 AI 自主渗透测试系统：给它一个目标和授权范围，它会像真实红队一样自己规划、派发子任务实际执行渗透、逐步逼近目标，全程可视化、可人工介入。 它区别于“给渗透工具接个 LLM”的地方，在于下面几个设计： 目标驱动的任务闭环 任务从「任务描述 + 目标」开始： 1. Plan（规划者） 根据任务描述和目标，生成探索方案（拆成一条条具体的探索意图）； 2. Work（执行者） 领取意图、独立执行，把结果写回图中； 3. Plan 再基于图里的新信息重新规划，一步步向目标收敛。 规划 → 执行 → 回写 → 再规划，如此循环，直到目标达成。整个过程是自我驱动的，不需要人来一步步喂指令。 任务与资产绑定 → 可量化的测试覆盖度 任务和资产是绑定的，因此可以直接衡量一个任务对目标的测试覆盖度——哪些资产测了、测到什么程度、还有哪些没覆盖，一目了然。 这解决了实战中的一个真痛点：目标定义往往是模糊的。很多时候你说不清“测到什么算完成”，于是可以反过来把覆盖度本身设成测试目标——比如“覆盖全部子域 / 全部开放端口 / 某类资产 100%”，让 AI 以达成覆盖度为收敛条件去自主推进。目标从“说不清”变成“可量化、可验收”。 一切都在一张图里，而不是塞进上下文 任务的资产、流量、探索意图、事实、漏洞发现统一组织成一张探索图谱，节点之间带父子/派生关系，资产与流量直接绑定到对应任务上下文。 好处是极大节省 LLM 上下文：Plan 看到的是这张图的结构化摘要，而不是把海量原始执行日志堆进 prompt。当它确实需要某个子任务的执行细节时，再通过工具按需拉取指定 work 的完整执行链路（命令、输出、每一步工具调用都在）。该省时省，该细时细。 流量录制：让 Agent 像人一样翻流量找问题 内置流量录制代理，把测试过程中的 HTTP 流量完整捕获下来——既包括 agent 自己发出的测试流量，也包括浏览器自动化操作产生的流量，全部落库并绑定到对应任务。 关键在于：这些流量不是只给人看的日志，而是开放给 agent 的一等数据。agent 可以像人工渗透时那样，搜索、筛选、逐条查看所有历史流量——翻参数、比对响应、串联跨请求的线索，从已有流量里挖出更多潜在问题（隐藏参数、越权、信息泄露、被忽略的接口……），而不是只盯着自己当前这一步。相当于给 AI 配了一个可随时检索的“全量流量记忆”。 两层 Agent：规划与执行分离 Plan 负责读图、判断攻击面、保持多条路线并行、避免过早收敛，还能对关键漏洞派专门的对抗式复现验证； Work 每个只领一条意图，聚焦执行真实工具（nmap/curl/ripgrep…），只把增量事实写回图谱，做完即停。 多个 work 可并发，天然并行探索。 自定义 Agent、自定义 LLM 自定义 LLM：支持 Anthropic / OpenAI 及兼容接口，provider、model、baseurl、代理均可在 UI 配置，私有模型或中转皆可； 自定义 Agent：可在界面里自定义 agent 的能力与工具集，按需裁剪或扩展。 拦截审批：给自主 Agent 装一道人工闸门 ARTEX 内置一套基于规则的工具调用拦截层：可按工具名、命令内容等自定义匹配规则，按优先级命中后执行三种动作之一—— allow：放行； deny：直接拦下并把原因反馈给模型，让它换条路； ask：暂停执行、推送给你人工审批，你批准才继续，可设超时与超时默认动作。 「AI 全自动跑」和「关键动作人工确认」不再二选一：日常探索让它自己飞，危险或不可逆的操作(如对生产目标的写操作)自动卡住等你放行，安全与效率兼得。 全程可视 + 人在环路 Token 消耗与活动流、任务执行过程与探索链路、漏洞与资产归档、流量录制、拦截审批（关键操作前人工放行）、随时对话介入纠偏。
