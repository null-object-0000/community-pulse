### 【开源自荐】TinyBERT Pipeline：多模型分工 + Node 编排 + Python 训练 + ONNX 推理的全自动 Agent 进化流水线 👤 MaskerPRC
> 阮老师好， 一直在读周刊，受益很多。最近业余时间做了一个小项目，想斗胆投个稿，若不合适请直接忽略就好。 项目叫 TinyBERT Pipeline，是一个 Agent 服务框架。我想强调的是：从「说一句话想要什么能力」到「线上真的用起来」，中间没有手工训练脚本、没有自己标数据、没有本地点下一步——整条链路都是程序自动跑的。 具体来说：意图分析、任务类型与模型架构选型、训练数据批量生成与校验、小模型训练与 ONNX 导出、工具注册、以及根据新能力自动重写核心流程代码（loop.js）并热替换，全部是自动化编排完成的；其中小模型训练也是由系统在后台调度 Python 训练流程、写完模型再注册进服务，不需要人单独开训练作业或填参数才能训一版。大模型主要负责请求兜底和驱动上述自动化流水线，高频重复的事会逐步被轻量推理接过去。 举个很简单的例子：在「进化」里用一句话写——「用户一开口就判断是否恶意，是的话直接回复：请好好说话」——系统会按意图选好任务类型和模型架构，自动生成训练数据、训好小模型并注册成工具，再改好 loop.js 让请求先过小模型分流。 流水线里不同步骤用不同模型，都在配置里可换（默认走 OpenRouter 统一接入）。大致分工是：GPT 系（如 openai/gpt5.4） 负责进化侧的意图分析和任务形态 + 轻量模型架构选型（分类 / NER / 相似度 / 回归该走哪条、FastText 到 DistilBERT 选哪档）；Gemini 一路负责真实用户对话（如 google/gemini3.1propreview），另一路用偏快偏省的 Flash 系（如 google/gemini2.5flashlite）做大批量训练数据生成与标注；Claude（如 anthropic/claudeopus4.6）专门做 loop.js 的生成与迭代，保证流程代码可热替换。线上「小」的一侧则是配置里的候选架构列表（如 fasttext,tinybert,minilm,distilbert），由系统自动按任务复杂度选够用最小的一档，训完用 ONNX / FastText 推理。 技术栈是 Express + Vue 3，推理 ONNX / FastText，训练侧 PyTorch。代码还很粗糙，欢迎拍砖。 仓库： 另外还有一个是视觉自训练流程： 谢谢阮老师长期整理资讯，祝周刊越办越好。

### 【开源自荐】Agent CPU：用 JS 控制流约束 Agent 规划，缓解 ReAct 式发散 👤 MaskerPRC
> 阮老师好， 冒昧自荐一个小项目，还在持续打磨，若有不当之处还请多指正。 Agent CPU（仓库： ）是一个 AI Agent 执行框架。和常见的 ReAct「一步步想、一步步动」不同，这里尝试让 LLM 直接产出可执行的 JavaScript 作为任务规划：框架负责依赖分析/安装、在沙箱里跑这段代码、出错时把反馈丢回给模型再规划一轮。 我们想多强调一层动机：大模型在预训练里见过大量代码，对 JavaScript 里的顺序、分支、循环等控制结构，本身就有很强的「语感」和遵循能力。 把规划写成 JS，相当于用 程序语言自带的结构 去约束 Agent 的推理路径——先做什么、再分支、循环到哪一步停，都落在熟悉的语法里，更容易 收敛到一条可执行、可检查的流程，而不是在纯自然语言步骤里越滚越长、越跑越散。这也是我们想和 ReAct 类方案区的一点：尽量缓解「发散」（步骤堆砌、偏离主线），用代码里的流程结构换一点 可预期的收敛。 同时，规划落到真实代码上，也比纯文本步骤更好复用和组合；调试 Agent 往往像在猜黑盒，所以用 Acorn 做了代码插桩，支持断点、步进（F10）、监视变量等，方便自己查问题。 技术栈：Node（Express + Socket.io）+ Vue 3，LLM 走 OpenAI 兼容接口；内建 llmcall、agentcall、gencall 等。水平有限，文档和边界情况都还在补。 若周刊读者里有做 Agent 或调试工具的朋友，欢迎试用、提 issue。也感谢阮老师长期整理周刊，让我们这些后来者能少走一点弯路。

### [开源推荐] clime: 统一 CLI 安装以及管理工具 👤 git-hulk
> 项目地址 类别 Go 项目标题 clime: 统一 CLI 安装以及管理工具 项目描述 随着 AI 开发范式逐步从 MCP 迁移到 CLI，追踪已安装的 CLI 并保持其最新状态变得越来越困难。对于拥有大量内部工具的组织而言，基本无法在统一的位置发现并下载这些工具。 clime 作为统一的 CLI 管理器，实现在一个 CLI 内管理和调用全部的工具。同时，通过一个数据源来安装多个工具，方便公司统一管理内部已有的工具集。 亮点 通过 YAML 配置统一安装 shell clime init [] 在一个工具内调用全部 CLI shell 通过 clime 安装 NPM 工具 $ clime plugin install opencli npm @jackwener/opencli 在 clime 调用 opencli $ clime opencli V 管理 CLI shell 查看已经安装 CLI $ clime plugin 卸载已经安装的 CLI $ clime plugin uninstall opencli 更新全部 CLI $ clime plugin update all 示例代码 markdown 截图或演示视频
