### [开源] 牵丝 Filaxis：给 AI Agent 用的远程执行运行时（SDK / CLI / MCP），附多跳 SSH 堡垒机 + Docker 对照实测 👤 Corolin
> 最近把自己在 Agent 项目里打磨了几套远程执行方案后沉淀出来的一层运行时开源了，叫 **牵丝 Filaxis**（Apache-2.0，TypeScript 实现，支持 Bun / Node），提供 **SDK、CLI 和 MCP Server** 三种接入方式。 - GitHub：https://github.com/corolin/filaxis - npm：`@syrkos/filaxis` ### 为什么要单独抽出来？ 最初只是想让 Agent 通过 SSH 管远程机器，但真跑起来之后，卡住 Agent 的往往不是 SSH 本身，而是执行链路里的工程细节： - **多层 Shell 转义翻车**：比如 `Windows PowerShell -> SSH 堡垒机 -> Linux -> Docker`，引号和转义一多，命令很容易在半路变形。 - **进程与子进程难收敛**：发了 `kill` 之后，远端进程树或后台子进程是否真正退出，缺乏可靠核实。 - **长时任务断线难接管**：命令跑得久、连接抖动或 Agent 会话重连时，状态容易丢。 - **Docker bind-mount 文件替换风险**：直接做普通原子替换，有时会碰上挂载点 / inode 相关的坑。 - **输出混流与上下文淹没**：stdout/stderr 混在一起，长日志把上下文撑爆，Agent 却拿不到明确的终态判断。 于是把这些拆成了几块能力：多层连接、长时会话观察、断线接管、终态核实、CAS 文件编辑、跨层批次任务，以及带校验的文件传输。 ### 跟裸 SSH 实际比过吗？ 做过四期受控对照测试，不光看单条命令延迟，更看端到端排障与文件传输的整体表现。 最近一轮在**同一模型 + 四套独立 Docker-in-Docker 沙盒**下对比了四组： - 原生 SSH - Filaxis CLI - Filaxis SDK - Filaxis MCP 链路设定为：从 Windows 出发，经过跨地域堡垒机（**禁用 TCP Forwarding，不能走 ProxyJump**）进入远端 Linux 与目标 Docker 容器。Agent 事先不知道容器名和故障文件路径，需要自行排查并修复 **9 处隐藏联动故障**，同时完成跨地域二进制文件上传、下载与 SHA-256 校验。 四组均通过验收。其中 **裸 SSH vs Filaxis MCP** 的一轮采样结果如下： | 指标 | 裸 SSH | Filaxis MCP | |---|---:|---:| | 完成耗时 | 483 秒 | 225 秒 | | 决策轮数 | 24 | 14 | | 活跃 Token | 107,151 | 81,297 | | 执行报错/摩擦 | 4 | 0 | 这轮 MCP 的耗时下降了 53.4%，活跃 Token 减少 24.1%。 需要说明的是，这只是单次受控实战采样，不是所有场景的普适结论。在路径明确、步骤很短的简单局域网任务里，裸 SSH 反而可能在 Token 和轮数上更省。完整的测试方法、各组数据、失败记录和局限性都在仓库的 `benchmark.md` 里。 ### 目前支持什么 & 快速上手 核心能力包括： - 多跳 SSH / Docker 进入与跨层批次编排 - 长时会话观察、断线后会话接管、终态核实 - CAS 文件编辑与带校验的文件传输 - MCP Server 接口，可直接接入支持 MCP 的 Agent 宿主 全局安装与查看 MCP 配置： ```bash npm install -g @syrkos/filaxis filaxis mcp-config ``` ### 当前边界 目前还是 `0.2.x` 阶段，**不是全平台生产级通用执行器**。Docker / K8s 等场景目前主要通过进入命令或适配接口接入，部分交互模式与 tmux watcher 接管仍有边界，欢迎在 issue 或讨论里一起踩坑、拍砖。 如果刚好折腾过 Agent 远程运维/排障，欢迎试用交流；如果觉得有点参考价值，也欢迎点个 Star ⭐ https://github.com/corolin/filaxis 千里一线，执行有迹。
