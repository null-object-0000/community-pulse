### 【工具自荐】SmartAutoFill —— SmartAutoFill 是一个 AI 表单自动填写 Chrome 扩展, BYOK 👤 chasays
> 项目名称 SmartAutoFill <img width="507" height="697" alt="Image" src=" / 项目简介 SmartAutoFill 是一个 AI 表单自动填写 Chrome 扩展，用来辅助填写重复性的网页表单，比如求职申请、Google Forms、CRM 表单、问卷、内部工具表单等。 它不是“自动提交机器人”，而是一个 reviewfirst 的表单填写助手：先扫描页面上的可见字段、标签、选项和上下文，再根据用户保存的资料生成填写草稿，最后由用户自己检查、修改和提交。 项目地址 官网： Chrome 扩展： 测试页面： GitHub： 核心功能与特点 现在很多网页表单并不是简单的姓名、邮箱、电话，而是会问很多需要上下文的问题，比如： 求职申请里的工作经历、项目经验、LinkedIn、GitHub、作品集链接 Google Forms 里的部门、角色、项目说明、常用问卷答案 CRM 或内部系统里的客户信息、公司简介、跟进备注 QA / 测试环境里需要反复填写的测试数据 SmartAutoFill 想解决的就是这类“浏览器自带自动填充不够用”的场景。 主要特点： 1. AI 理解表单上下文 会读取可见字段、label、placeholder、select 选项、页面标题和附近文本，尽量理解每个字段真正要填什么。 2. 支持多种使用场景 适合求职申请、Google Forms、CRM 数据录入、问卷、内部工具、QA 测试表单等重复填写场景。 3. Reviewfirst，不自动提交 工具只负责生成和填写草稿，不会自动点击提交按钮。用户可以先检查、修改，再手动提交，避免误填重要表单。 4. 对敏感字段更保守 对密码、支付、验证码、身份信息、法律确认、同意勾选等敏感字段，会尽量避免自动填写或提醒用户人工处理。 5. 提供测试页面 官网有一个 AI form filler test page，可以先在模拟表单上测试扩展效果，再用于真实工作流。 为什么推荐它？ 很多人现在已经习惯用 AI 写简历、整理资料、生成回答，但真正填网页表单时，还是要在不同页面之间反复复制粘贴。尤其是海外求职、CRM 录入、Google Forms、内部后台这些场景，字段很多、格式不统一，非常消耗时间。 SmartAutoFill 的思路不是替用户“盲目自动提交”，而是把 AI 用在更安全的位置：理解表单、生成草稿、辅助填写，然后让用户自己最终确认。 如果你经常填写求职申请、问卷、客户资料、内部系统表单，或者需要在测试环境反复填表，这个工具可以节省不少重复输入的时间。

### 【工具自荐】庖丁.skill —— 你收藏了 100 个 AI Skill，说得出任何一个为什么好用吗？ 👤 longyunfeigu
> 项目名称 庖丁.skill 项目简介 庖丁.skill 是一个 Claude Code skill，用来把任何 AI skill 包（SKILL.md / prompt workflow / agent playbook）解成一本可以在浏览器里翻的解剖手册。 你收藏了 100 个 skill，说不出其中任何一个为什么好用。软件工程时代你还能钻进源码——但 skill 没有源码可读。skill 的「源码」，是它对模型默认行为的改变。庖丁读的就是这个。 为什么推荐它？ 现在 AI skill / prompt engineering 的生态有一个奇怪的现象：好的 skill 越来越多，但「学会写好 skill」的路径几乎不存在。你能找到几百个 awesomeprompts 列表，但没有一个能告诉你「这条规则为什么不能删」「这个中间产物选这个格式而不是那个格式，背后的洞察是什么」。 传统软件有源码可读、有设计文档可查，但 skill 的核心是自然语言规则对模型行为的约束——它的「源码」不在代码里，在它对默认行为的改变里。这层东西，不拆开对比，看不见。 庖丁的思路不是「给你一个功能清单」，而是「带你走一遍，让你自己看见」——先看没有这个 skill 时 AI 会怎么坏，再看它用什么机制防住，最后标出哪些招能搬进你自己的项目。每个论断标证据等级，是猜的标猜，不确定的标不确定。 如果你在写自己的 AI skill、在学习别人的 prompt workflow、或者想搞懂「为什么这个 agent 的效果比默认好这么多」，庖丁能帮你把黑箱拆成白箱。 项目地址 GitHub： <img width="1480" height="868" alt="Image" src=" / <img width="1196" height="1585" alt="Image" src=" / <img width="1480" height="1450" alt="Image" src=" / 核心功能与特点 现在越来越多人用 Claude Code skill、prompt workflow、agent playbook 来控制 AI 的行为。但 skill 的学习曲线很陡：一个好的 skill 包可能有几千行规则、十几个引用文件、自定义脚本——光读一遍都费劲，更别说搞懂「为什么这条规则不能删」「这个中间产物为什么要存成这个格式」。 庖丁想解决的就是「看不懂好 skill 为什么好」的问题。 主要特点： 不读功能，读反事实 对包里的每条规则、每个脚本、每个中间产物，过三问：去掉它第一个坏掉的产物是什么？这个坏结果对基线是默认发生还是小概率？凭什么相信？——每个论断都带证据等级（实测 / 作者证词 / 结构推断 / 假设），是猜的标猜。 七维度难点扫描 + 六镜头带走点 难点按来源分七个维度（任务难、执行者不可靠、规模超上下文、品味说不清、输入残缺、环境怪癖），归不进的进残渣清单。然后再换六个镜头（痛点 / 知识 / 概念 / 话术 / 验法 / 产物形状）扫一遍，把「读者明天干活就能直接拿走的东西」挑出来，在正文的机制现场用「📌 可带走」标注。 手册不是摘要，是沉浸式走查 手册主体以 AI 的第一人称带你把 skill 从头跑一遍——每一站先看拿到了什么、默认会怎么坏、让你先猜怎么防，然后才贴出 skill 的原文。猜错一次比听懂十次记得牢，这条是构建层硬约束，缺了直接构建失败。 机器强制的质量门禁 症状缺证据标记 → 构建拒绝；有难点的站缺预测点 → 拒绝；术语缺实例 → 拒绝；场景再现没有实物片段 → 拒绝。凡是只写在规格里、没进 gate 的教学规则，第二本手册就全丢了——没进 gate 的规则必然退化，这是庖丁自己的命题在自己身上的验证。 三种输出模式，按需取用 快速评审：直接给 keep/cut 建议，哪些该删该留 模式提取：把可迁移的 skill 设计模式提出来 完整手册：六章 + 三附录的 Web 解剖手册（Overview / 实战走查 / 中间产物与数据流 / 源包导读 / 难点档案 / Apply It + 术语表 / 带走工具箱 / 源码附录） 脚本必跑铁律 源包里的脚本，只要有合法输入，必须逐个真跑。解女娲 skill 时，跑它自带的 qualitycheck.py，发现出厂示例跑不过出厂检查器——光读代码只敢说「实现较脆」，跑两条命令之后，它成了整本手册里最硬的发现。

### 〖工具自荐〗ego lite：让 Codex/Claude Code 复用真实浏览器登录态跑网页任务 👤 Davidyooo
> 项目地址： 官网/下载： 使用文档： ego lite 是一个给人类和 AI Agent 共用的的 Chromium 浏览器。 我们做它的原因来源于自身的痛点：现在用 Codex、Claude Code、Cursor 这类 Agent 做网页任务时，经常会遇到几个麻烦：临时浏览器没有登录态、Cookie/插件/SSO 迁移麻烦，遇到验证码或后台系统时容易卡住；同时 Agent 操作浏览器时，也容易和我们正在使用的标签页互相打扰。 ego lite 想解决的是这个问题：让人和 Agent 使用同一个浏览器环境，但在不同的 Space 里工作。你可以继续正常浏览网页，Agent 则在自己的独立 Space 里打开网页、读取页面、点击、填写表单、抓取信息或完成重复性网页任务。 几个特点： 通过 egobrowser skill 接入 Codex、Claude Code、Cursor 等 Agent，不绑定特定模型或内置 Agent。 可以迁移 Chrome 的登录态、Cookie、扩展、书签和 Profile，让 Agent 直接处理需要登录的网站。 每个任务可以运行在独立 Space 中，适合并行处理多个网页任务，也不会抢走当前标签页。 针对 Agent 提供语义化页面 Snapshot，并支持在页面内一次执行多步操作，减少传统「一步一工具调用」带来的等待和 token 消耗。 适合处理邮箱、CRM、SaaS 后台、社媒、招聘、订票、表单填写、内部系统等 API 不完整但网页可操作的场景。 浏览数据保留在本机，历史记录、Cookie、密码和页面内容不会上传云端。 目前 ego lite 支持 macOS，Windows / Linux 正在路上，ego lite 浏览器可以免费下载使用。 我自己最常用的场景是：让 Codex 打开多个网页做信息比对，进入已登录的 SaaS 后台拉取数据，或者批量处理一些原本只能手动点网页完成的流程。 如果周刊读者正在尝试把 Codex、Claude Code 这类 Agent 用到真实网页工作流里，希望 ego lite 能省掉「登录态迁移」和「Agent 抢标签页」这两个很烦的小问题。
