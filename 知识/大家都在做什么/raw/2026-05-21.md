### 【文章推荐】为什么 AI 指令应该优先写“不该做什么” 👤 wizardpisces
> 禁止项给的是框架，框架内部才是自由。正向清单给的是路径，路径之外全是禁区。 指令设计的直觉往往导向“应该做什么”。产品经理、提示词工程师、普通用户，第一反应几乎都是描述期望：你应该礼貌、应该详细、应该主动追问。 但正向清单存在一个无法解决的缺陷：它不可能穷举。没有设计者能遍历所有场景，而大模型作为概率系统，在未被明确指引的灰色地带会本能地选择“讨好”——帮用户合理化一个糟糕的决策，为明显错误的命题寻找论据支撑。这并非模型“坏”，而是“提供帮助”在训练信号里的权重天然高于“指出错误”。 这正是禁止指令优先论的逻辑起点。禁止项的本质，不是束缚，而是重新定义什么叫“帮助”。 摘自

> 项目地址 类别 人工智能 项目标题 帮 AI Agent 编写系统提示词的 Skill 项目描述 这是一个面向 Codex / Claude Code 风格环境的 Skill，用来帮助 code agent 为其他 agent 项目编写可部署的 system prompt，覆盖角色定义、任务边界、工具规则、证据来源、输出格式和失败处理。 亮点 解决 AI 直接写 system prompt 时常见的角色乱推、工具 API 幻觉、schema 字段泄漏、提示词过长和不可部署说明混入等问题。 README 与评估说明为中文，Skill 正文和 references 保持英文，兼顾中文用户阅读和 agent 运行时理解。 内置 prompt engineering principles、domain adaptation、tool contract 和 evaluation checklist。 提供 .codex/INSTALL.md，包含 macOS / Linux / Windows 的安装、验证、更新和卸载步骤。 带 MIMO 兼容 eval runner 和 test/ 评估用例，当前自测 with skill 平均通过率 0.917，without skill 平均通过率 0.554。 示例代码 text 请使用 $agentsystempromptarchitect 我想做一个中文学习助手 agent，主要给高中生和大学低年级学生用。 它需要能解释课程知识点、根据用户上传资料回答问题、整理错题、制定复习计划。 系统里可能会有检索用户资料、检索课程知识库、保存错题、生成学习计划等工具， 但我还没有确定真实工具名、参数和返回格式。 帮我写一个可以直接放进 system message 的系统提示词。 截图或演示视频 暂无。
