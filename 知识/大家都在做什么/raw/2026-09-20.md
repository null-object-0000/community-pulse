### Pace — Pi coding agent 的桌面 GUI（开源 / early） 👤 kieranx
> 大家好！介绍一下 Pace ，给 Pi coding agent 用的桌面 GUI 。 TL;DR Pace 是一个为 Pi Coding Agent 打造的开源桌面 GUI Workbench （基于 Electron + React ）。它不是简单的 API 套壳，而是把 Pi 作为后端独立引擎驱动的工作台，提供可视化的执行轨迹、Diff 审查、Token 成本透视以及子代理观察能力。 GitHub： https://github.com/BubblePtr/pace ![home page]( https://raw.githubusercontent.com/bubbleptr/pace/main/docs/assets/readme/home.png) **1 、为什么做 Pace?** 平时高强度使用终端里的 Coding Agent （如 Pi ）时，常常遇到几个痛点： - 滚屏混乱与失焦：任务一长、Tool Call 一多，几十屏的日志很难快速回溯「它刚才具体改了什么、哪一步报错了」。 - Diff 审查与终端挤占：代码改动需要反复切另外的 git 工具去看，或者在命令行里看折叠 diff ，不够直观。 - Token 与成本黑盒：很多工具只给一个最后的花销，中间过程每一步吃了多少 context 、cache 命中情况到底怎样，缺少真凭实据。 - 子代理（ Subagent ）观测困难：多 agent 协作或并发长任务时，终端里交错的日志基本没法看。 - 既然 Pi 的架构本身把底层 Engine 和扩展能力做得非常干净，那最顺手的形态应该是一个像 IDE 一样的桌面 Workbench ，而不是只留在终端里。 **2 、 它和常见的套壳工具有什么区别** - 直接集成 Pi 官方 SDK：Pace 不是在外部起一个 CLI 命令做文本解析，而是直接集成 Pi 官方 SDK （基于 SDK Driver / createAgentSession 驱动 Agent 运行时）。Pi 本地的 Session 日志是唯一数据源，终端里跑过的会话可以直接在 Pace 中打开，所有原生的配置、插件和会话数据完全同构复用。 - 把舞台留给插件：专设插件面板（ Extension Surfaces ）：我们不想把所有功能做死在主界面，而是为插件提供可视化的舞台。在 Session Dock 中规划了专属的插件面板接口。未来各类插件不再局限于在终端里打日志，而是可以按插件自身需求，注册并渲染独特的交互窗口（例如子代理树状拓扑、自定义工作流检查器、测试结果仪表盘等）。 - Session Dock 边聊边看：侧边集成 Changes (Diff 审查)、Files 、Terminal 、Browser 等面板，审代码、看终端输出不需要反复切屏。 - Trajectory 轨迹与成本真相：完整的执行轨迹流，细化到每一步 Tool Call 的耗时、入参/返回，以及真实的 Token 与费用账单。 - 子代理链路观察：支持关联到子会话回放（ Subagent ），不再是一团黑盒。 **3 、技术实现与架构** - 桌面壳：Electron （主进程 + utilityProcess 独立运行后端 + React 渲染层）。 - 前端架构：React 19 + TypeScript + Astryx 设计系统规范。 - 通信与状态：进程隔离，通过规范化的事件流做状态投影，保证长任务或断网崩溃时主界面不卡顿、数据不丢。 **4 、目前状态与交流** 目前项目处于早期快速迭代阶段，基础的工作流和 Trajectory / Diff / 子代理观测链路已经可用。 想和大家交流： 大家平时更习惯纯 CLI 的 Agent 交互，还是希望有一个专门的 GUI 工作台来辅助审查和调度？ 在多 Agent 或复杂工作流场景下，你最希望在 GUI 上看到哪些维度的信息？ 欢迎试用体验、提 Issue 或拍砖！
