### 【开源自荐】DApp Inspector：在 Chrome DevTools 里查看 DApp 与钱包之间的全部 RPC 通信 👤 beilunyang
> DApp Inspector 是一个 Chrome 扩展。装上之后 DevTools 里会多出一个面板，按时间顺序展示当前 tab 里 DApp 与 Web3 钱包（MetaMask、Rabby、OKX Wallet 等）之间所有的 JSONRPC 调用 —— 包括完整入参、返回值、错误、时延分解、链 ID、calldata 自动解码，以及一套用于调试的 Block / Throttle / Mock / Replay 规则引擎。 项目地址： Chrome 商店： 介绍页： 它解决什么问题？ DApp 与钱包之间的 RPC 通信对开发者来说一直是个黑盒： 网页点一个按钮，钱包跳出来要签什么、签名前后做了哪些 ethcall 探测、传了什么 calldata，从外面看不到。 MetaMask 自带的 activity log 只能看自己钱包发出去的请求，看不到 DApp 一侧的时延、参数处理、错误分支。 调试 DApp 的异常路径（钱包拒绝、网络超时、合约 revert）需要手工构造各种边界条件。 想复现用户反馈的奇怪 bug，需要还原他当时与钱包之间的完整调用序列。 之前我一直靠在 window.ethereum 上手动打 monkey patch 加日志，每个项目都要重写一遍，效率很低。索性做成扩展，所有 DApp 通用。 主要特性 全量捕获 拦截 window.ethereum.request 的所有调用，自动分类为 read / write / sign / subscribe 兼容 EIP6963 多钱包并存场景 完整记录入参、返回值、错误对象，原始 JSONRPC envelope 一键复制 时延分解 把一次调用拆成 6 段单独计时：DApp 发起 → 扩展排队 → throttle → 钱包审批 → RPC 往返 → 回到 DApp。可以一眼看出瓶颈是用户审批还是 RPC 节点。 Calldata 自动解码 内置 ERC20 / 721 / 1155 / Permit2 的 ABI，命中即 0ms 解码 命中不到时按 chainId + 合约地址 查 Sourcify，再降级到 4byte 选择器 拉到的 ABI 本地缓存 7 天，跨页面复用 对 ethsendTransaction / ethsignTransaction 会额外做风险评分（无限授权、setApprovalForAll 等） 调试规则引擎 Block —— 按方法名/origin 匹配，拒掉某些请求并返回自定义错误码，验证 DApp 的错误处理分支 Throttle —— 给匹配的请求加延迟，复现慢网络、loading state、超时分支 Mock —— 用预设结果短路掉某个调用，不真实上链 Replay —— 任何捕获到的调用都能重放一次，JSON 参数现场可编辑，钱包按原流程再次弹窗 隐私与本地化 全部在浏览器本地运行，没有 telemetry、没有账号、没有数据上传 ABI 解析的 Sourcify / 4byte 是按需才请求（和加载网页图片同一性质） 简体中文 / English 双语界面 适合谁使用？ DApp 前端开发者：调试合约调用、签名流程、错误分支 钱包扩展开发者：观察 DApp 一侧的调用模式和兼容性问题 安全审计 / 反钓鱼研究者：分析未知 DApp 调用了哪些方法、传了什么 calldata、有没有可疑的授权 想了解某个 DApp "幕后到底做了什么" 的 Web3 用户 技术栈 Chrome Manifest V3 TypeScript / React 18 / Zustand / Tailwind Vite + @crxjs/viteplugin Vitest（单元）+ Playwright（端到端） 协议：Apache2.0 截图 DevTools 面板（捕获列表 + 详情）： !panel 调用详情（参数 / 返回值 / 时延 / ReplayMockBlock）： !detail Options 页（规则管理）： !options 目前只支持 EVM，Solana / Sui 等其他生态在规划中。欢迎试用、提 issue、贡献代码。另外 README 末尾写了一个 logo 招募说明 —— 如果有设计师朋友感兴趣，欢迎一起完善这个项目。

### 【开源自荐】EverOS：一个让 AI Agent 拥有长期记忆的开源系统，内置大量真实 Use Cases 👤 Yangtze-Seventh
> EverOS 是一个开源的 AI Agent 长期记忆系统，目标是让 Agent 不再每次从零开始，而是能在不同会话、不同任务、不同工作流中持续记住上下文，并从过往经验中自动沉淀可复用的 Skills。 项目地址： 官网： 文档： EverOS 仓库里不只是一个记忆框架，还整理了很多可运行、可参考的真实 Use Cases，展示长期记忆可以怎样接入 Coding Agent、浏览器 Agent、AI companion、游戏 NPC、可穿戴设备、多 Agent 协作等场景。 <img width="2640" height="1404" alt="Image" src=" / 为什么 Agent 需要长期记忆？ 现在很多 AI Agent 很强，但最大的问题是“健忘”： 每次新会话都要重新介绍项目背景、用户偏好和任务目标。 Agent 做过一次任务，下次遇到类似问题还是重新摸索。 普通 RAG 更像查资料，很难保存 Agent 的操作过程、错误修正和成功经验。 多 Agent 协作时，不同 Agent 很难共享长期上下文。 EverOS 想解决的是这个问题：让 Agent 能记住自己做过什么、用户喜欢什么、项目约定是什么，以及哪些流程下次可以直接复用。 核心能力 1. Selfevolving Skill Memory EverOS 会记录 Agent 执行任务的轨迹，把一次次任务过程沉淀成 Cases，再从重复出现的成功路径中自动提炼出 Skills。 这意味着 Agent 可以逐渐学会： 某个项目常用的开发、测试、部署流程 用户喜欢的输出格式和沟通方式 某类问题过去如何成功解决 哪些工具、命令、文件和检查步骤最常用 下次再遇到类似任务时，Agent 可以直接复用已有 Skills，而不是从零推理。 <img width="2618" height="1186" alt="Image" src=" / 2. 多类型记忆 EverOS 区分不同类型的 Agent 记忆： Profile Memory：长期身份、偏好、角色和表达方式 Episodic Memory：过去发生过的事件、会话和任务历史 Procedural Memory：流程、技能和操作方式 Semantic Memory：事实、概念和长期知识 这让它既可以支持个人助手，也可以支持 Coding Agent、团队 Agent、多 Agent 系统和 AI companion。 <img width="2642" height="958" alt="Image" src=" / 3. mRAG 多模态写入与检索 EverOS 支持通过统一 API 处理多种资料类型，包括 URL、图片、PDF、Word、表格、PPT、邮件、HTML 和文本。 它使用 hybrid retrieval，把语义检索和关键词匹配结合起来，让 Agent 能在复杂资料里更准确地找到相关上下文。 <img width="2658" height="1186" alt="Image" src=" / Use Cases EverOS 最有意思的地方是，它不是只停留在框架层，而是已经有很多场景案例。下面是一些仓库里展示的方向。 <img width="1396" height="1318" alt="Image" src=" / 1. Coding Agent 的项目长期记忆 EverOS 可以接入 Claude Code、Codex、Cursor、Gemini CLI 等 Coding Agent，让它们记住一个项目的长期上下文。 例如： repo 结构 常用命令 代码规范 测试方式 团队习惯 过去踩过的坑 已经验证过的修复路径 这样 Coding Agent 每次进入项目时，不只是临时读文件，而是能继承过去的开发经验。 2. MultiAgent Orchestration Platform 多 Agent 系统里，不同 Agent 需要分工协作：有的负责规划，有的负责写代码，有的负责测试，有的负责研究。 EverOS 可以提供共享记忆层，让多个 Agent 共享项目级上下文，同时保留各自的执行经验。这样一个 Agent 学到的经验，可以被后续 Agent 复用。 4. Study Buddy with SelfEvolving Memory 学习助手如果有长期记忆，就可以记住学生的知识水平、薄弱点、学习节奏和历史错误。 EverOS 可以让 Study Buddy 根据长期学习轨迹调整辅导方式，并把有效的学习路径沉淀成可复用经验。 仓库结构 EverOS 仓库主要分为三部分： Use cases：各种长期记忆应用案例和集成示例 Architecture methods：可运行、可扩展的记忆架构，比如 EverCore、HyperMem Benchmarks：评估记忆质量和 Agent 自进化能力的开放基准，比如 EverMemBench、EvoAgentBench 如果只是想快速理解长期记忆能做什么，可以先看 Use cases；如果想接入自己的 Agent，可以从 EverCore 开始；如果想做评测，可以看 Benchmarks。 适合谁？ 正在做 AI Agent / Coding Agent / 多 Agent 系统的开发者 想给现有 AI 应用增加长期记忆能力的团队 做个人助手、AI companion、游戏 NPC、浏览器 Agent、可穿戴 AI 的产品团队 研究 Agent memory、自进化 Agent、长期一致性和个性化 AI 的研究者 技术栈：Python、TypeScript、JavaScript 许可证：Apache2.0

> CodeRAG 是一个基于 Python、Treesitter、ChromaDB 与 HuggingFace Transformers 构建的本地代码库 RAG（检索增强生成）工具，专为大规模代码仓库设计。它通过 MCP 协议对外暴露服务，让 Claude Code、OpenCode 等 AI 编程助手获得代码库级别的上下文理解能力，即使面对数十万行代码的项目也不在话下，全程代码不出本机。
