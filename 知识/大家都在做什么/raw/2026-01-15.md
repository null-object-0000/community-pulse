### 【漏洞修复】314000+下载量的hyperlane框架被曝安全漏洞 👤 eastspire
> 近日，Rust 轻量级web框架hyperlane被开源社区发现严重安全漏洞，攻击者可利用进行提权等操作。 安全与行为回退问题说明 在长连接（keepalive） 场景下，同一个实例可能被多次复用，进而导致跨请求的上下文状态泄露。 ctx 的生命周期并未按单个请求完全隔离，这是一个长期存在的设计缺陷，而非本次改动新引入的问题。 近期的一次代码修改进一步暴露了该问题：它导致 ctx.aborted() 和 ctx.closed() 方法无法正常工作，从而破坏了请求拦截逻辑与生命周期钩子函数的执行。 问题相关代码路径： 影响范围 1. ctx.aborted() 和 ctx.closed() 无法再正确反映连接的实际状态 2. 请求拦截功能与基于生命周期的控制逻辑失效 3. 长连接场景下，单个 ctx 实例会被多个请求复用，造成跨请求上下文状态泄露 修复方案 1. v10.23.1 版本 — 恢复了 ctx.aborted() 的功能与生命周期拦截逻辑，修复提交： 2. v10.23.3 版本 — 确保长连接下 ctx 实例不再被复用，彻底杜绝跨请求上下文状态泄露问题，修复提交： 升级建议 强烈建议用户升级至 v10.23.3 或更高版本，以保障请求隔离与生命周期管理功能正常运行。 最简复现示例 在存在问题的代码版本中，访问 时，控制台会依次输出 "Middleware1 reached" 和 "Middleware2 reached"。 而 "Middleware2 reached" 的输出属于不符合预期的行为，因为第一个中间件理论上应该终止后续的生命周期处理流程。 rust use hyperlane::; struct Middleware1; struct Middleware2; impl ServerHook for Middleware1 { async fn new(ctx: &hyperlane::Context) Self { Self } async fn handle(self, ctx: &Context) { println!("Middleware1 reached"); ctx.aborted().await; } } impl ServerHook for Middleware2 { async fn new(ctx: &hyperlane::Context) Self { Self } async fn handle(self, ctx: &Context) { println!("Middleware2 reached"); } } [tokio::main] async fn main() { Server::new() .await .requestmiddleware::<Middleware1() .await .requestmiddleware::<Middleware2() .await .run() .await .unwrap() .wait() .await; } 测试未发现该问题的原因 该问题在测试阶段未被发现，是因为单测代码覆盖场景不全，测试用例仅通过响应结果判断请求是否发送成功，而非检测控制台输出内容。 框架在发送响应前，会执行实时的中断状态检查。因此当上下文被标记为中断时，响应不会被处理或发送，从响应层面无法发现异常。 修复后代码仓库
